    Хранилище браузера¶

    ID
    WSTG-CLNT-12

    Резюме¶

    Браузеры предоставляют разработчикам следующие механизмы клиентского хранилища для сохранения и извлечения данных:

    • LocalStorage
    • SessionStorage
    • IndexedDB
    • Cookies

    Данные механизмы хранения можно просматривать и редактировать с помощью встроенных инструментов разработчика браузера, таких как Google Chrome DevTools или Firefox Storage Inspector.

    Note: Хотя кэш браузера также является формой хранилища, он рассматривается в отдельном разделе, посвященном его специфическим особенностям и угрозам.

    Цели тестирования¶

    • Определить, сохраняет ли сайт конфиденциальные данные в клиентских хранилищах.
    • Проанализировать код, взаимодействующий с объектами хранилищ, на предмет потенциальных атак внедрения (injection), таких как использование непроверенного ввода или уязвимых сторонних библиотек.

    Методика тестирования¶

    LocalStorage¶

    Свойство window.localStorage — это глобальное свойство, реализующее Web Storage API и предоставляющее долговременное (persistent) хранилище вида «ключ-значение» в браузере.

    И ключи, и значения могут быть исключительно строками, поэтому любые нестроковые значения должны быть предварительно сериализованы в строки перед сохранением — как правило, с помощью метода JSON.stringify.

    Записи в localStorage сохраняются даже после закрытия окна браузера, за исключением окон в приватном режиме (Private/Incognito).

    Максимальный объем хранилища localStorage различается в зависимости от браузера.

    Вывод всех пар «ключ — значение»¶

    for (let i = 0; i < localStorage.length; i++) {
  const key = localStorage.key(i);
  const value = localStorage.getItem(key);
  console.log(`${key}: ${value}`);
}

    SessionStorage¶

    Свойство window.sessionStorage — это глобальное свойство, реализующее Web Storage API и предоставляющее эфемерное (сессионное / ephemeral) хранилище вида «ключ-значение» в браузере.

    И ключи, и значения могут быть только строками, поэтому любые нестроковые структуры должны быть предварительно преобразованы в строки перед помещением в хранилище (обычно с помощью JSON.stringify).

    Записи в sessionStorage являются временными и автоматически уничтожаются при закрытии соответствующей вкладки или окна браузера.

    Максимальный объем хранилища sessionStorage варьируется в разных браузерах.

    Вывод всех пар «ключ — значение»¶

    for (let i = 0; i < sessionStorage.length; i++) {
  const key = sessionStorage.key(i);
  const value = sessionStorage.getItem(key);
  console.log(`${key}: ${value}`);
}

    IndexedDB¶

    IndexedDB — это транзакционная объектно-ориентированная база данных, предназначенная для хранения структурированных данных. База данных IndexedDB может содержать несколько объектных хранилищ (object stores), а каждое объектное хранилище — множество объектов.

    В отличие от localStorage и sessionStorage, IndexedDB позволяет хранить не только строки. В IndexedDB можно сохранять любые объекты, поддерживаемые алгоритмом структурированного клонирования (structured clone algorithm).

    Примером сложного JavaScript-объекта, который может храниться в IndexedDB, но не поддерживается в localStorage/sessionStorage, являются криптографические ключи CryptoKey.

    Рекомендация W3C по Web Crypto API предписывает, чтобы ключи CryptoKey, требующие долговременного сохранения в браузере, размещались в IndexedDB. При тестировании веб-страницы найдите любые ключи CryptoKey в IndexedDB и проверьте, установлено ли для них свойство extractable: true, когда должно быть extractable: false (то есть необходимо убедиться, что закрытый ключ ни при каких обстоятельствах не раскрывается в открытом виде во время криптографических операций).

    Вывод всего содержимого IndexedDB¶

    const dumpIndexedDB = dbName => {
  const DB_VERSION = 1;
  const req = indexedDB.open(dbName, DB_VERSION);
  req.onsuccess = function() {
    const db = req.result;
    const objectStoreNames = db.objectStoreNames || [];

    console.log(`[*] Database: ${dbName}`);

    Array.from(objectStoreNames).forEach(storeName => {
      const txn = db.transaction(storeName, 'readonly');
      const objectStore = txn.objectStore(storeName);

      console.log(`\t[+] ObjectStore: ${storeName}`);

      // Вывод всех записей в objectStore с именем `storeName`
      objectStore.getAll().onsuccess = event => {
        const items = event.target.result || [];
        items.forEach(item => console.log(`\t\t[-] `, item));
      };
    });
  };
};

indexedDB.databases().then(dbs => dbs.forEach(db => dumpIndexedDB(db.name)));

    Файлы cookie¶

    Cookies представляют собой механизм хранения пар «ключ-значение», преимущественно применяемый для управления сессиями, однако веб-разработчики могут использовать его для сохранения произвольных строковых данных.

    Тематика cookie подробно раскрыта в сценарии тестирования атрибутов Cookies.

    Вывод списка всех cookie¶

    console.log(window.document.cookie);

    Глобальный объект Window¶

    Иногда веб-разработчики инициализируют и поддерживают глобальное состояние, доступное только во время жизненного цикла страницы, путем назначения пользовательских атрибутов глобальному объекту window. Например:

    window.MY_STATE = {
  counter: 0,
  flag: false,
};

    Любые данные, привязанные к объекту window, будут безвозвратно утеряны при перезагрузке или закрытии страницы.

    Вывод всех свойств объекта Window¶

    (() => {
  // создание iframe и добавление в body для загрузки чистого объекта window
  const iframe = document.createElement('iframe');
  iframe.style.display = 'none';
  document.body.appendChild(iframe);

  // получение текущего списка свойств объекта window
  const currentWindow = Object.getOwnPropertyNames(window);

  // фильтрация свойств по сравнению с эталонным чистым окном
  const results = currentWindow.filter(
    prop => !iframe.contentWindow.hasOwnProperty(prop)
  );

  // удаление вспомогательного iframe
  document.body.removeChild(iframe);

  // логирование различающихся записей "ключ-значение"
  results.forEach(key => console.log(`${key}: ${window[key]}`));
})();

    (Модифицированная версия данного фрагмента кода)

    Последствия для безопасности¶

    При анализе механизмов браузерного хранилища тестировщикам необходимо оценивать, не раскрываются ли конфиденциальные данные необоснованно на клиентской стороне. Современные приложения, в особенности одностраничные приложения (Single Page Applications, SPA), часто сохраняют токены аутентификации или состояние приложения в хранилище браузера, что может создавать серьезные риски безопасности.

    К распространенным угрозам относятся:

    • Токены аутентификации (например, JSON Web Tokens, JWT), сохраненные в localStorage или sessionStorage, к которым имеет прямой доступ JavaScript, что делает их уязвимыми к перехвату через XSS.
    • Токены или идентификаторы сессий, сохраняющиеся после выхода пользователя из системы (logout).
    • Конфиденциальные бизнес-данные, хранящиеся в IndexedDB или localStorage без явной производственной необходимости.
    • Криптографические ключи, помеченные как доступные для экспорта (extractable: true), в то время как они должны быть защищены.

    Некорректное использование клиентского хранилища существенно повышает степень опасности клиентских атак, таких как DOM-based XSS.

    Общее руководство по тестированию¶

    Помимо перечисления записей в хранилищах, тестировщикам следует:

    • Анализировать хранилища браузера с помощью инструментов разработчика (вкладка Application / Storage).
    • Идентифицировать токены аутентификации, сессионные идентификаторы и конфиденциальные бизнес-данные.
    • Попытаться получить доступ к сохраненным значениям через консоль JavaScript.
    • Проверить, очищаются ли записи хранилищ после завершения сеанса (logout) или по истечении срока действия сессии.
    • Оценить, могут ли сохраненные данные использоваться в цепочках атак на стороне клиента.

    Цепочка атаки¶

    После выявления любого из вышеперечисленных векторов атак может быть сформирована комплексная цепочка эксплуатации с другими видами клиентских атак — в частности, с атаками DOM-based XSS.

    Рекомендации по устранению¶

    Приложения должны сохранять конфиденциальные данные на стороне сервера, а не на клиенте, безопасным образом в соответствии с лучшими отраслевыми практиками.
