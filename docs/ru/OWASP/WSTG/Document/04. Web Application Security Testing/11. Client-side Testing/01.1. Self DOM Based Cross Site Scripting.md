# Self DOM-based межсайтовый скриптинг (Self DOM-based XSS)

## Резюме

Собственный межсайтовый скриптинг на основе DOM (Self DOM-Based Cross-Site Scripting, Self DOM XSS) представляет собой специфическую атаку, требующую предварительного понимания DOM-based XSS и успешного применения методов социальной инженерии (social engineering). Термин «self» (собственный) указывает на то, что пользователю необходимо самостоятельно внедрить полезную нагрузку в поле ввода и, таким образом, исполнить уязвимость против самого себя. Специфика данной уязвимости также заключается в том, что политика защиты контента (Content Security Policy, CSP) веб-сайта способна блокировать выполнение скриптов.

В данном сценарии термин «приёмник» (sink) используется в следующем значении: в вычислительной технике приёмник (sink), приёмник событий (event sink) или приёмник данных (data sink) — это класс или функция, предназначенная для получения входных данных или событий от другого объекта или функции. Таким образом, для выявления потенциальных уязвимостей в первую очередь необходимо идентифицировать приёмники в тестируемом приложении.

## Методика тестирования

Процесс тестирования на Self DOM-Based Cross-Site Scripting выглядит следующим образом:

1. Найти уязвимые приёмники, принимающие пользовательский ввод.
2. После идентификации потенциального приёмника внедрить полезную нагрузку (payload).
3. Проверить журнал ошибок в инструментах разработчика браузера (Developer Tools), чтобы оценить результат и сделать выводы.
4. Проверить, способен ли атакующий убедить пользователя вставить пейлоад без необходимости обладания глубокими техническими знаниями.

### Пример

Данный конкретный пример взят из этого [отчёта HackerOne](https://hackerone.com/reports/406587).

В примере на веб-сайте `https://example.com` выполняется следующая функция JavaScript:

```javascript
//Marketo Form Code
function strip(html) {
    var tmp = document.createElement("DIV");
    tmp.innerHTML = html;
    return tmp.textContent || tmp.innerText || "";
}

$('form').submit(function() {
    $('textarea').val(function() {
        return strip($(this).val());
    });
});
```

Эксплуатацию данной функциональности можно описать следующим образом:

1. Обработчик события `submit` передает текущее значение всех элементов `textarea` в функцию `strip`.
2. Эта функция создает новый элемент `div` и присваивает свойству `innerHTML` переданное значение.
3. На последнем этапе она возвращает свойство `textContent` полученного элемента `div`.

Подобный код обычно используется для удаления HTML-тегов из строки, поскольку свойство `textContent` содержит текст, визуализированный браузером при парсинге HTML. Данный конкретный метод изначально небезопасен, поскольку использует `innerHTML`. Когда пользовательский ввод передается в свойство `innerHTML`, он разбирается веб-браузером и, следовательно, может привести к выполнению вредоносного JavaScript.

Для проверки уязвимости можно использовать следующий пейлоад: `<img src=x onerror=alert(1) />`.

Консоль разработчика отобразит две ошибки: одну с указанием на то, что был запрошен адрес `https://www.example.com/x`, вернувший статус 404 (из-за атрибута src тега img), и вторую, сообщающую о нарушении политики CSP веб-сайта.

Вторая ошибка возникла потому, что браузер попытался выполнить код JavaScript в атрибуте `onerror`, однако политика CSP веб-сайта заблокировала его выполнение. Повторение тех же действий в браузере с отключенной CSP привело к успешному исполнению JavaScript в атрибуте `onerror`.

Злоумышленник мог бы проэксплуатировать данную уязвимость, убедив пользователя вставить вредоносный пейлоад в поле «message» контактной формы и затем нажать кнопку «send message». Атака могла бы быть усилена путем склонения пользователя к использованию устаревшей версии браузера без поддержки CSP.
