# Выполнение JavaScript

| ID |
| --- |
| WSTG-CLNT-02 |

## Резюме

Уязвимость внедрения кода JavaScript (JavaScript Injection) представляет собой подтип межсайтового скриптинга (Cross-Site Scripting, XSS), связанный с возможностью внедрения произвольного кода JavaScript, выполняемого приложением в браузере жертвы. Данная уязвимость может иметь множество последствий — от утечки сессионных cookie пользователя, которые могут быть применены для олицетворения жертвы, до общей модификации отображаемого контента страницы или изменения логики поведения приложения.

Уязвимости внедрения JavaScript возникают при отсутствии должной валидации входных данных пользователя и экранирования выходных данных на стороне приложения. Поскольку JavaScript применяется для динамического наполнения веб-страниц, внедрение происходит на этапе обработки контента и непосредственно затрагивает браузер жертвы.

При тестировании на данную уязвимость учитывайте, что некоторые символы обрабатываются разными браузерами по-разному. Дополнительную информацию см. в разделе [DOM-based XSS](https://owasp.org/www-community/attacks/DOM_Based_XSS).

Ниже приведен пример сценария, который не выполняет никакой валидации переменной `rr`. Данная переменная принимает пользовательский ввод из строки запроса (query string) и не подвергается никакому кодированию:

```javascript
var rr = location.search.substring(1);
if(rr) {
    window.location=decodeURIComponent(rr);
}
```

Это означает, что злоумышленник может внедрить код JavaScript, просто передав следующую строку запроса: `www.victim.com/?javascript:alert(1)`.

## Цели тестирования

- Идентифицировать приёмники (sinks) и потенциальные точки внедрения кода JavaScript.

## Методика тестирования

Рассмотрим страницу, содержащую следующий скрипт:

```html
<script>
function loadObj(){
    var cc=eval('('+aMess+')');
    document.getElementById('mess').textContent=cc.message;
}

if(window.location.hash.indexOf('message')==-1) {
    var aMess='({"message":"Hello User!"})';
} else {
    var aMess=location.hash.substr(window.location.hash.indexOf('message=')+8)
}
</script>
```

Приведенный выше код содержит источник (source) `location.hash`, контролируемый атакующим, который может напрямую внедрить в значение `message` исполняемый код JavaScript для перехвата управления браузером пользователя.
