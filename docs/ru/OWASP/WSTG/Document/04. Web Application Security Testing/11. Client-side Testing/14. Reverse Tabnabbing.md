# Обратный табнаббинг (Reverse Tabnabbing)

| ID |
| --- |
| WSTG-CLNT-14 |

## Резюме

[Обратный табнаббинг](https://owasp.org/www-community/attacks/Reverse_Tabnabbing) (Reverse Tabnabbing) — это атака, используемая для перенаправления пользователей на фишинговые страницы. Обычно она становится возможной, когда атрибут `target` тега `<a>` установлен в значение `_blank`, из-за чего ссылка открывается в новой вкладке. Если в том же теге `<a>` не указан атрибут `rel='noopener noreferrer'`, вновь открытая страница получает доступ к исходной странице через свойство `window.opener` и может перенаправить её на подконтрольный атакующему домен.

Поскольку пользователь изначально находился на легитимном домене до открытия новой вкладки, он с меньшей вероятностью заметит подмену страницы в исходной вкладке, особенно если фишинговая страница визуально идентична оригинальному сайту. Любые учетные данные, введенные на подконтрольном злоумышленнику домене, попадут в распоряжение атакующего.

Ссылки, открываемые с помощью функции JavaScript `window.open`, также подвержены данной атаке.

_NOTE: [Современные браузеры](https://caniuse.com/mdn-html_elements_a_implicit_noopener) обрабатывают ссылки с `target="_blank"` так, как если бы атрибут `rel="noopener"` был задан неявно, поэтому обычные ссылки уязвимы только в устаревших браузерах (например, в версиях до Google Chrome 88). Ссылки с `rel="opener"` и страницы, открытые через `window.open()` без параметра `noopener` в свойствах окна (window features), по-прежнему уязвимы в современных браузерах._

### Пример

Представьте веб-приложение, позволяющее пользователям указывать URL в своем профиле. Если приложение уязвимо к обратному табнаббингу, злоумышленник может разместить ссылку на страницу со следующим содержимым:

```html
<html>
 <body>
  <script>
    window.opener.location = "https://example.org";
  </script>
<b>Error loading...</b>
 </body>
</html>
```

Переход по такой ссылке откроет новую вкладку, в то время как исходная вкладка будет перенаправлена на «example.org». Если «example.org» визуально схож с уязвимым веб-приложением, пользователь вряд ли заметит подмену и с высокой долей вероятности введет свои конфиденциальные данные на этой странице.

## Цели тестирования

- Идентифицировать ссылки и вызовы `window.open()`, открывающие новую вкладку или окно без директивы `noopener`.
- Оценить, способна ли страница, открытая из приложения, изменить адрес исходной страницы через `window.opener`.

## Методика тестирования

- Проверьте HTML-код приложения на предмет того, содержат ли ссылки с `target="_blank"` ключевые слова `noopener` и `noreferrer` в атрибуте `rel`. Если нет, высока вероятность, что приложение уязвимо к обратному табнаббингу. Такая ссылка становится эксплуатируемой, если она указывает на сторонний скомпрометированный ресурс либо контролируется пользователем. Также проанализируйте JavaScript-код на наличие вызовов `window.open()`, в которых не передается параметр `noopener` в параметрах окна.
- Найдите области, где пользователь может внедрять произвольные ссылки (то есть контролировать атрибут `href` тега `<a>`). Попробуйте вставить ссылку на страницу с кодом из приведенного выше примера и проверьте, происходит ли перенаправление исходного домена. В современных браузерах это сработает только для ссылок с `rel="opener"` или страниц, открытых через `window.open()`; проверка обычных ссылок `target="_blank"` требует использования устаревших версий браузеров.

## Рекомендации по устранению

Рекомендуется убедиться, что HTML-атрибут `rel` содержит директивы `noreferrer` и `noopener` для всех внешних ссылок, а при вызовах `window.open()` параметр `noopener` передается в конфигурации окна (window features).
