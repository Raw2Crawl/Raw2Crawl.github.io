# HTML-инъекция

| ID |
| --- |
| WSTG-CLNT-03 |

## Резюме

Внедрение HTML-кода (HTML Injection) — это тип уязвимости внедрения (injection), возникающий в ситуациях, когда пользователь контролирует точку ввода и способен внедрить произвольный HTML-код в уязвимую веб-страницу. Данная уязвимость способна повлечь за собой множество негативных последствий, таких как раскрытие сессионных cookie пользователя с возможностью последующей компрометации его учетной записи или, в более общем плане, модификацию отображаемого для жертвы содержимого страницы.

Данная уязвимость возникает в том случае, когда пользовательский ввод не проходит надлежащую очистку (sanitization), а выходные данные не кодируются (output encoding). Внедрение позволяет злоумышленнику доставить вредоносную HTML-страницу жертве. Браузер целевого пользователя не способен отличить доверенные легитимные компоненты страницы от вредоносных включений и в результате выполняет синтаксический анализ и рендеринг всей страницы целиком в контексте безопасности пользователя.

Существует широкий спектр методов и атрибутов, применяемых для отрисовки HTML-содержимого. Если в эти методы передаются недоверенные входные данные, возникает высокий риск появления уязвимости внедрения HTML. Например, вредоносный HTML-код может быть внедрен через JavaScript-свойство `innerHTML`, обычно используемое для вывода пользовательского HTML-кода. Если входные строки должным образом не обезвреживаются, данное свойство открывает возможность для HTML-инъекции. Еще одной функцией JavaScript, часто используемой в подобных целях, является `document.write()`.

В следующем примере продемонстрирован фрагмент уязвимого кода, использующий непроверенный ввод для формирования динамического HTML в контексте страницы:

```javascript
var userposition=location.href.indexOf("user=");
var user=location.href.substring(userposition+5);
document.getElementById("Welcome").innerHTML=" Hello, "+user;
```

В следующем примере показан уязвимый код, использующий функцию `document.write()`:

```javascript
var userposition=location.href.indexOf("user=");
var user=location.href.substring(userposition+5);
document.write("<h1>Hello, " + user +"</h1>");
```

В обоих случаях уязвимость может быть проэксплуатирована с использованием следующего значения параметра:

```text
https://vulnerable.site/page.html?user=<img%20src='aaa'%20onerror=alert(1)>
```

Такой ввод приведет к добавлению на страницу тега изображения, который выполнит произвольный код JavaScript, внедренный злоумышленником в HTML-контекст.

## Методика тестирования

Рассмотрим следующий код HTML и сценарий JavaScript:

```html
<script src="../js/jquery-1.7.1.js"></script>
<script>
function setMessage(){
    var t=location.hash.slice(1);
    $("div[id="+t+"]").text("The DOM is now loaded and can be manipulated.");
}
$(document).ready(setMessage  );
$(window).bind("hashchange",setMessage)
</script>
<body>
    <script src="../js/embed.js"></script>
    <span><a href="#message" > Show Here</a><div id="message">Showing Message1</div></span>
    <span><a href="#message1" > Show Here</a><div id="message1">Showing Message2</div>
    <span><a href="#message2" > Show Here</a><div id="message2">Showing Message3</div>
</body>
```

Существует возможность внедрения HTML-кода.
