# XPath-инъекция (XPath Injection)

| ID |
| --- |
| WSTG-INJT-09 |

## Резюме

XPath представляет собой язык, разработанный главным образом для адресации и выборки элементов XML-документа. В рамках тестирования на внедрение XPath-кода (XPath Injection) проверяется возможность инъекции синтаксических конструкций XPath в запросы, обрабатываемые приложением, что позволяет злоумышленнику выполнять произвольные запросы XPath. В случае успешной эксплуатации данная уязвимость позволяет обойти механизмы аутентификации или получить доступ к конфиденциальным данным без соответствующих полномочий.

Веб-приложения активно используют базы данных для хранения и извлечения рабочей информации. Исторически наиболее распространенной технологией хранения данных оставались реляционные СУБД, однако в последние годы растет популярность баз данных, структурирующих данные с помощью языка XML. Подобно тому, как к реляционным базам обращаются с помощью языка SQL, в XML-базах данных стандартным языком запросов выступает XPath.

Поскольку с концептуальной точки зрения XPath во многом схож с SQL по назначению и принципам применения, атаки типа XPath Injection строятся по той же логике, что и [внедрение SQL-кода (SQL Injection)](https://owasp.org/www-community/attacks/SQL_Injection). В определенных аспектах XPath даже мощнее стандартного SQL, так как весь его функционал изначально заложен в спецификацию, тогда как многие техники SQL-инъекций зависят от диалекта конкретной СУБД. Это делает атаки XPath Injection более универсальными и переносимыми. Другим преимуществом для атакующего является то, что в отличие от SQL здесь не применяются списки управления доступом (Access Control Lists, ACL) — сформированный запрос может получить доступ к любой части XML-документа.

## Цели тестирования

- Идентифицировать точки внедрения XPath-кода.

## Методика тестирования

[Вектор атаки на XPath был впервые опубликован Амитом Кляйном (Amit Klein)](https://dl.packetstormsecurity.net/papers/bypass/Blind_XPath_Injection_20040518.pdf) и концептуально аналогичен классическому внедрению SQL-кода. Для наглядности рассмотрим форму аутентификации веб-приложения, в которой пользователь вводит логин и пароль. Предположим, что база данных представлена следующим XML-файлом:

```xml
<?xml version="1.0" encoding="ISO-8859-1"?>
<users>
    <user>
        <username>gandalf</username>
        <password>!c3</password>
        <account>admin</account>
    </user>
    <user>
        <username>Stefan0</username>
        <password>w1s3c</password>
        <account>guest</account>
    </user>
    <user>
        <username>tony</username>
        <password>Un6R34kb!e</password>
        <account>guest</account>
    </user>
</users>
```

Запрос XPath, возвращающий учетную запись с именем `gandalf` и паролем `!c3`, выглядит следующим образом:

`string(//user[username/text()='gandalf' and password/text()='!c3']/account/text())`

Если приложение не выполняет надлежащую фильтрацию пользовательского ввода, тестировщик может внедрить код XPath и повлиять на результат выполнения запроса. Например, можно передать следующие значения:

```text
Username: ' or '1' = '1
Password: ' or '1' = '1
```

С учетом этих параметров результирующий запрос примет вид:

`string(//user[username/text()='' or '1' = '1' and password/text()='' or '1' = '1']/account/text())`

Как и в случае классической SQL-инъекции, сформированный запрос всегда возвращает истинное значение (true). В результате приложение выполнит успешную аутентификацию пользователя даже без предоставления корректного логина или пароля. И так же, как при тестировании на SQL Injection, первым шагом при поиске XPath Injection является внедрение одинарной кавычки (`'`) в проверяемое поле для вызова синтаксической ошибки и проверки реакции приложения на некорректный ввод.

Если внутренняя структура XML-данных неизвестна, а приложение не выводит информативных сообщений об ошибках, позволяющих восстановить логику запроса, можно применить технику [слепого внедрения XPath (Blind XPath Injection)](https://owasp.org/www-community/attacks/Blind_XPath_Injection), целью которой является поэтапная реконструкция структуры данных. Данная методика аналогична логическому выводу при слепой SQL-инъекции (inference-based SQL Injection): в запрос внедряются конструкции, возвращающие один бит информации (истина/ложь). Подробнее техника [Blind XPath Injection](https://owasp.org/www-community/attacks/Blind_XPath_Injection) описана в исследовании Амита Кляйна.
