# Внедрение инструкций SSI (SSI Injection)

| ID |
| --- |
| WSTG-INJT-08 |

## Резюме

Веб-серверы обычно предоставляют разработчикам возможность внедрять небольшие фрагменты динамического кода внутрь статических HTML-страниц без необходимости использования полноценных серверных или клиентских языков программирования. Эта возможность обеспечивается механизмом [вставок на стороне сервера (Server-Side Includes, SSI)](https://owasp.org/www-community/attacks/Server-Side_Includes_%28SSI%29_Injection).

Server-Side Includes представляют собой директивы, которые веб-сервер разбирает перед отправкой страницы пользователю. Они являются альтернативой написанию CGI-программ или внедрению кода с помощью серверных скриптовых языков, когда требуется выполнять лишь очень простые задачи. Стандартные реализации SSI предоставляют директивы (команды) для включения внешних файлов, установки и вывода CGI-переменных окружения веб-сервера, а также для выполнения внешних CGI-скриптов или системных команд.

SSI может приводить к удаленному выполнению команд (Remote Command Execution, RCE), однако в большинстве веб-серверов директива `exec` отключена по умолчанию.

Эта уязвимость во многом схожа с классической инъекцией в скриптовые языки. Одним из факторов снижения риска является то, что веб-сервер должен быть специально сконфигурирован для поддержки SSI. С другой стороны, уязвимости внедрения SSI-директив (SSI Injection) зачастую проще в эксплуатации, поскольку директивы SSI легко воспринимаются и при этом обладают значительной мощностью: например, они могут выводить содержимое файлов и выполнять системные команды.

## Цели тестирования

- Идентифицировать точки внедрения SSI-директив.
- Оценить степень критичности инъекции.

## Методика тестирования

Для проверки возможности эксплуатации SSI внедрите директивы SSI в качестве пользовательского ввода. Если поддержка SSI включена и валидация пользовательского ввода не реализована должным образом, сервер выполнит указанную директиву. Это очень похоже на классическую уязвимость внедрения в скриптовые языки в том смысле, что она возникает, когда пользовательские данные не подвергаются надлежащей валидации и санитизации.

Сначала определите, поддерживает ли веб-сервер директивы SSI. Зачастую ответ утвердительный, так как поддержка SSI весьма распространена. Чтобы выяснить, поддерживаются ли директивы SSI, определите тип веб-сервера целевой системы с помощью методов сбора информации (см. раздел [Fingerprint Web Server](../01.%20Information%20Gathering/02.%20Fingerprint%20Web%20Server.md)). При наличии доступа к исходному коду проверьте, используются ли директивы SSI, выполнив поиск специфических ключевых слов в файлах конфигурации веб-сервера.

Другой способ проверить включение директив SSI — поиск страниц с расширением `.shtml`, которое традиционно ассоциируется с директивами SSI. Использование расширения `.shtml` не является обязательным, поэтому отсутствие файлов `.shtml` само по себе не означает, что цель не уязвима к атакам SSI Injection.

Следующий шаг заключается в определении всех возможных векторов пользовательского ввода и проверке возможности эксплуатации инъекции SSI.

Сначала найдите все страницы, где разрешен ввод пользовательских данных. Возможные векторы ввода также могут включать заголовки и файлы cookie. Определите, как входные данные сохраняются и используются — например, возвращаются ли они в сообщении об ошибке или элементе страницы и модифицируются ли они каким-либо образом. Доступ к исходному коду может помочь точнее определить векторы ввода и алгоритм их обработки.

Составив список потенциальных точек внедрения, определите, корректно ли валидируется ввод. Убедитесь в возможности внедрения символов, используемых в директивах SSI, таких как `<!#=/."->` и `[a-zA-Z0-9]`.

Приведенный ниже пример возвращает значение переменной. Раздел [ссылок](#ссылки-и-материалы) содержит полезные ресурсы с документацией по конкретным серверам для более точной оценки конкретной системы:

```html
<!--#echo var="VAR" -->
```

При использовании директивы `include`, если указанный файл является CGI-скриптом, эта директива включит вывод этого CGI-скрипта. Данная директива также может использоваться для вставки содержимого файла или вывода списка файлов в каталоге:

```html
<!--#include virtual="FILENAME" -->
```

Для вывода результата выполнения системной команды:

```html
<!--#exec cmd="OS_COMMAND" -->
```

Если приложение уязвимо, директива внедряется и будет интерпретирована сервером при следующей отдаче страницы.

Директивы SSI также могут внедряться в HTTP-заголовки, если веб-приложение использует эти данные для динамического формирования страницы:

```text
GET / HTTP/1.1
Host: www.example.com
Referer: <!--#exec cmd="/bin/ps ax"-->
User-Agent: <!--#include virtual="/proc/version"-->
```
