# Загрузка файлов неожиданных типов

| ID |
| --- |
| WSTG-BUSL-08 |

## Резюме

Бизнес-процессы многих приложений предусматривают загрузку и обработку данных, передаваемых в виде файлов. Однако бизнес-процесс обязан проверять файлы и допускать к обработке только строго определенные «разрешенные» типы файлов. Определение того, какие файлы считаются «разрешенными», задается бизнес-логикой и специфично для конкретного приложения или системы. Риск заключается в том, что, позволяя пользователям загружать файлы, система может получить от злоумышленников непредусмотренный тип файла, который в случае выполнения способен нанести серьезный ущерб приложению или инфраструктуре: привести к дефейсу сайта, выполнению произвольных команд на сервере, чтению системных файлов и локальных ресурсов, организации атак на другие серверы или эксплуатации локальных уязвимостей.

Уязвимости, связанные с загрузкой файлов непредусмотренных типов, специфичны тем, что механизм загрузки должен быстро отклонять файл, если он не имеет требуемого расширения. Кроме того, это отличается от загрузки вредоносных файлов тем, что в большинстве случаев некорректный формат файла сам по себе может не являться заведомо «вредоносным», но способен повредить сохраняемые данные. Например, если приложение принимает файлы Microsoft Excel, загрузка файла базы данных со схожей структурой может быть прочитана обработчиком, однако извлеченные данные попадут в неверные таблицы или поля.

Приложение может ожидать для обработки файлы только определенных типов, такие как `.csv` или `.txt`. При отсутствии валидации загружаемых файлов по расширению (низкий уровень доверия) или по содержимому (высокий уровень доверия) это может привести к непредвиденным сбоям в системе или базе данных либо предоставить злоумышленникам дополнительные векторы для компрометации приложения и системы.

### Пример

Предположим, сервис обмена изображениями позволяет пользователям загружать на сайт графические файлы `.gif` или `.jpg`. Что произойдет, если злоумышленник сможет загрузить файл HTML с тегом `<script>` внутри или PHP-скрипт? Система может переместить файл из временной директории в постоянную общедоступную папку, откуда PHP-код может быть выполнен на сервере с компрометацией приложения или операционной системы.

## Цели тестирования

- Изучить проектную документацию на предмет типов файлов, которые должны отклоняться системой.
- Убедиться, что нежелательные типы файлов отклоняются и обрабатываются безопасно.
- Проверить, что пакетная (групповая) загрузка файлов безопасна и не позволяет обойти установленные защитные механизмы.

## Методика тестирования

### Конкретный метод тестирования

- Изучите логические требования приложения.
- Подготовьте набор «неразрешенных» для загрузки файлов, включающий файлы с расширениями `.jsp`, `.exe` или HTML-файлы, содержащие исполняемые скрипты.
- В приложении перейдите к форме или механизму отправки/загрузки файлов.
- Отправьте «неразрешенный» файл на загрузку и убедитесь, что приложение корректно блокирует операцию.
- Проверьте, не ограничивается ли сайт валидацией типа файла исключительно в клиентском JavaScript.
- Проверьте, не определяет ли сайт тип файла только по заголовку `Content-Type` в HTTP-запросе.
- Проверьте, не проверяет ли сайт тип файла исключительно по расширению его имени.
- Проверьте, можно ли получить прямой доступ к загруженным файлам по статическому URL.
- Проверьте, может ли загружаемый файл содержать инъекции исполняемого кода или скриптов.
- Проверьте наличие контроля путей к файлам (file path checking). В частности, злоумышленники могут упаковать файлы с заданными путями в ZIP-архив (Zip Slip), чтобы распакованные файлы после загрузки и декомпрессии оказались в непредусмотренных каталогах файловой системы.

## Рекомендации по устранению

Приложения должны разрабатываться с использованием механизмов, принимающих и обрабатывающих только строго «допустимые» файлы, которые остальная функциональность приложения готова и ожидает корректно обработать. В частности, рекомендуется применять: белые списки (allowlist) расширений файлов, проверку заголовка `Content-Type`, а также сигнатурный анализ типов файлов (magic numbers / file type recognizer), допуская в систему только проверенные форматы данных.
