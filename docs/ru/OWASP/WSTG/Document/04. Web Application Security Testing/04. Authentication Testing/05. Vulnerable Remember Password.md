# Уязвимая функция запоминания пароля (Remember Password)

| ID |
| --- |
| WSTG-ATHN-05 |

## Резюме

Учетные данные (credentials) представляют собой наиболее широко используемую технологию аутентификации. Из-за повсеместного применения пар «логин-пароль» пользователи больше не способны должным образом управлять своими учетными записями во всем множестве используемых приложений.

Для помощи пользователям в работе с учетными данными появилось несколько технологий:

- Функционал «запомнить меня» (*remember me*), предоставляемый приложениями, который позволяет пользователю оставаться аутентифицированным в течение длительного времени без необходимости повторного ввода учетных данных.
- Менеджеры паролей (включая встроенные менеджеры паролей браузеров), позволяющие безопасно хранить учетные данные и впоследствии автоматически подставлять их в формы ввода без какого-либо вмешательства со стороны пользователя.

## Цели тестирования

- Убедиться, что генерируемая сессия управляется безопасно и не подвергает учетные данные пользователя риску компрометации.

## Методика тестирования

Поскольку эти методы повышают удобство использования и избавляют пользователя от необходимости помнить пароли, они одновременно увеличивают поверхность атаки (attack surface). Некоторые приложения:

- Сохраняют учетные данные в закодированном виде в хранилищах браузера, что можно проверить в рамках сценария [тестирования веб-хранилищ](../11.%20Client-side%20Testing/12.%20Browser%20Storage.md) и сценариев [анализа сессий](../06.%20Session%20Management%20Testing/01.%20Session%20Management%20Schema.md#анализ-сессий). Учетные данные ни в коем случае не должны храниться в клиентском приложении и должны заменяться токенами, сгенерированными на стороне сервера.
- Автоматически подставляют учетные данные пользователя, что может быть проэксплуатировано в ходе следующих атак:
    - [Кликджекинг (Clickjacking)](../11.%20Client-side%20Testing/09.%20Clickjacking.md).
    - [Подделка межсайтовых запросов (Cross-Site Request Forgery, CSRF)](../06.%20Session%20Management%20Testing/05.%20Cross%20Site%20Request%20Forgery.md).
- Токены необходимо исследовать на предмет времени их жизни (token lifetime), поскольку некоторые токены никогда не истекают и ставят безопасность пользователей под угрозу в случае их перехвата или кражи. Обязательно выполните сценарий тестирования [времени ожидания сессии (session timeout)](../06.%20Session%20Management%20Testing/07.%20Session%20Timeout.md).

## Рекомендации по устранению

- Следуйте рекомендациям по [управлению сессиями](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
- Убедитесь, что никакие учетные данные не сохраняются в открытом виде (clear text) и не могут быть легко извлечены в закодированном или зашифрованном виде из механизмов хранения браузера; они должны храниться на стороне сервера с соблюдением стандартов [безопасного хранения паролей](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
