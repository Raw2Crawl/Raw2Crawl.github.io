# Учетные данные по умолчанию

| ID |
| --- |
| WSTG-ATHN-02 |

## Резюме

Многие веб-приложения и аппаратные устройства имеют пароли по умолчанию (default credentials) для встроенной учетной записи администратора. Хотя в некоторых случаях они могут генерироваться случайным образом, зачастую они являются статическими, то есть могут быть легко угаданы или получены злоумышленником.

Кроме того, при создании новых пользователей в приложениях для них могут устанавливаться предопределенные пароли. Они могут генерироваться как автоматически самим приложением, так и задаваться вручную сотрудниками. В обоих случаях, если они сгенерированы небезопасным образом, злоумышленник может подобрать такие пароли.

## Цели тестирования

- Определить, есть ли в приложении учетные записи пользователей с паролями по умолчанию.
- Проверить, создаются ли новые учетные записи с использованием слабых или предсказуемых паролей.

## Методика тестирования

### Учетные данные производителя по умолчанию

Первым шагом к выявлению паролей по умолчанию является определение используемого программного обеспечения. Данный процесс подробно описан в разделе руководства [Information Gathering](../01.%20Information%20Gathering/README.md).

После идентификации программного обеспечения необходимо выяснить, использует ли оно пароли по умолчанию, и если да, то какие именно. Для этого следует:

- Выполнить поиск по запросу "`[SOFTWARE]` default password".
- Изучить руководство пользователя или документацию вендора.
- Проверить общедоступные базы данных паролей по умолчанию, такие как [CIRT.net](https://cirt.net/passwords), [SecLists Default Passwords](https://github.com/danielmiessler/SecLists/tree/master/Passwords/Default-Credentials) или [DefaultCreds-cheat-sheet](https://github.com/ihebski/DefaultCreds-cheat-sheet/blob/main/DefaultCreds-Cheat-Sheet.csv).
- Проанализировать исходный код приложения (при его наличии).
- Установить приложение на виртуальную машину и исследовать его.
- Осмотреть физическое оборудование на наличие наклеек (стикеров), которые часто присутствуют на сетевых устройствах.

Если пароль по умолчанию найти не удается, попробуйте распространенные варианты, такие как:

- "admin", "password", "12345" или другие [распространенные пароли по умолчанию](https://github.com/nixawk/fuzzdb/blob/master/bruteforce/passwds/default_devices_users%2Bpasswords.txt).
- Пустой пароль.
- Серийный номер или MAC-адрес устройства.

Если имя пользователя неизвестно, существуют различные способы перечисления учетных записей (user enumeration), описанные в руководстве [Account Enumeration](../03.%20Identity%20Management%20Testing/04.%20Account%20Enumeration%20and%20Guessable%20User%20Account.md). В качестве альтернативы можно использовать стандартные имена учетных записей, такие как "admin", "root" или "system".

### Стандартные пароли организации

Когда сотрудники организации вручную создают пароли для новых учетных записей, они могут делать это предсказуемым образом. Зачастую это:

- Единый общий пароль, например "Password1".
- Сведения, специфичные для организации, такие как ее наименование или адрес.
- Пароли, составленные по простому шаблону, например "Monday123", если аккаунт был создан в понедельник.

Подобные типы паролей часто трудно обнаружить методом «черного ящика» (black-box testing), если только их не удастся успешно подобрать или перебрать по словарю (brute-force). Однако их легко выявить в рамках тестирования методом «серого» (gray-box) или «белого ящика» (white-box).

### Пароли по умолчанию, генерируемые приложением

Если приложение автоматически генерирует пароли для новых учетных записей пользователей, они также могут оказаться предсказуемыми. Чтобы проверить это, создайте в приложении одновременно несколько учетных записей со схожими данными и сравните выданные им пароли.

Пароли могут формироваться на основе:

- Единой статической строки, используемой для всех аккаунтов.
- Хешированной или обфусцированной части данных учетной записи, например `md5($username)`.
- Алгоритма, основанного на текущем времени.
- Слабого генератора псевдослучайных чисел (Pseudo-Random Number Generator, PRNG).

Уязвимости такого рода также зачастую сложно выявить при тестировании методом черного ящика.
