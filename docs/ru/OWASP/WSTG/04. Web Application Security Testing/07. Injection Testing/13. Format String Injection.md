# Внедрение строки форматирования

| ID |
| --- |
| WSTG-INJT-13 |

## Резюме

Строка формата (format string) представляет собой завершающуюся нулевым байтом последовательность символов, содержащую спецификаторы преобразования (conversion specifiers), которые интерпретируются или конвертируются во время выполнения программы. Если серверный код [конкатенирует пользовательский ввод со строкой формата](https://www.invicti.com/blog/web-security/string-concatenation-format-string-vulnerabilities), атакующий может передать дополнительные спецификаторы преобразования, что способно вызвать ошибку времени выполнения (runtime error), раскрытие конфиденциальной информации или переполнение буфера (buffer overflow).

Наиболее опасные последствия уязвимостей внедрения строк формата (Format String Injection) проявляются в языках, которые не проверяют соответствие аргументов типам и поддерживают спецификатор `%n`, осуществляющий запись значений по адресу в памяти. Эксплуатация таких функций путем манипулирования строкой формата может привести к [раскрытию информации и выполнению произвольного кода](https://en.wikipedia.org/wiki/Uncontrolled_format_string):

- C и C++: [printf](https://en.cppreference.com/w/c/io/fprintf) и родственные функции `fprintf`, `sprintf`, `snprintf`
- Perl: [printf](https://perldoc.perl.org/functions/printf.html) и `sprintf`

Следующие функции форматирования не позволяют выполнять прямую запись в память, однако атакующие все еще могут спровоцировать утечку данных, модифицируя строки формата для вывода непредусмотренных разработчиками значений:

- Python: метод [str.format](https://docs.python.org/3/library/stdtypes.html#str.format) может быть проэксплуатирован путем внедрения строк формата, обращающихся к [другим переменным](https://lucumr.pocoo.org/2016/12/29/careful-with-str-format/) в текущем контексте форматирования

Следующие функции форматирования могут вызывать ошибки времени выполнения при добавлении спецификаторов преобразования:

- Java: [String.format](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/lang/String.html#format%28java.util.Locale%2Cjava.lang.String%2Cjava.lang.Object...%29) и [PrintStream.format](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/io/PrintStream.html#format%2528java.util.Locale%252Cjava.lang.String%252Cjava.lang.Object...%2529)
- PHP: [printf](https://www.php.net/manual/es/function.printf.php)

Паттерн уязвимого кода заключается в вызове функции форматирования строк, принимающей несанитизированный пользовательский ввод. Следующий пример демонстрирует, как отладочный вызов `printf` может сделать программу уязвимой:

Пример на C:

```c
char *userName = /* input from user controlled field */;

printf("DEBUG Current user: ");
// Vulnerable debugging code
printf(userName);
```

Пример на Java:

```java
final String userName = /* input from user controlled field */;

System.out.printf("DEBUG Current user: ");
// Vulnerable code:
System.out.printf(userName);
```

В данном примере, если атакующий передаст в параметре `userName` один или несколько спецификаторов преобразования, возникнет аномальное поведение программы. Код на C [раскроет содержимое стека и памяти](https://www.defcon.org/images/defcon-18/dc-18-presentations/Haas/DEFCON-18-Haas-Adv-Format-String-Attacks.pdf), если `userName` содержит последовательность `%p%p%p%p%p`, а наличие спецификатора `%n` может повредить данные в памяти. В примере на Java передача в `username` любого спецификатора, требующего аргумента (включая `%x` или `%s`), приведет к аварийному завершению программы с исключением `IllegalFormatException`. Данная уязвимость устраняется явной передачей спецификатора в статическом шаблоне: `printf("DEBUG Current user: %s", userName)`.

## Цели тестирования

- Оценить, приводит ли внедрение спецификаторов формата в контролируемые пользователем поля к непредусмотренному поведению приложения.

## Методика тестирования

Тестирование включает в себя статический анализ исходного кода и внедрение спецификаторов преобразования в качестве пользовательского ввода в проверяемое приложение.

### Статический анализ

Инструменты статического анализа (Static Application Security Testing, SAST) позволяют выявлять уязвимости строк формата как в исходном коде, так и в скомпилированных бинарных файлах. Примеры инструментов:

- C и C++: [Flawfinder](https://dwheeler.com/flawfinder/)
- Java: правило FindSecurityBugs [FORMAT_STRING_MANIPULATION](https://find-sec-bugs.github.io/bugs.htm#FORMAT_STRING_MANIPULATION)
- PHP: анализатор String formatter Analyzer в [phpsa](https://github.com/ovr/phpsa/blob/master/docs/05_Analyzers.md#function_string_formater)

### Ручной анализ кода

Статический анализ может пропустить нетривиальные случаи, например когда строки формата динамически собираются сложной логикой приложения. При ручном аудите кодовой базы тестировщик должен найти все вызовы функций, принимающих строку формата, и отследить потоки данных, чтобы убедиться, что недоверенный ввод не может влиять на форматирующую строку.

### Внедрение спецификаторов преобразования

Тестировщики могут выполнять проверки на уровне модульных или комплексных системных тестов, передавая спецификаторы преобразования в любые строковые параметры. Проведите [фаззинг (Fuzzing)](https://owasp.org/www-community/Fuzzing) приложения, используя наборы спецификаторов для всех языков программирования, применяемых в целевой системе. Возможные варианты входных пейлоадов приведены на странице [OWASP Format string attack](https://owasp.org/www-community/attacks/Format_string_attack). При наличии уязвимости программа аварийно завершит работу либо сформирует непредусмотренный вывод. В случае защищенного приложения попытка внедрения спецификатора будет либо заблокирована, либо строка обработается как обычный текстовый литерал без каких-либо побочных эффектов.

Примеры в следующих подразделах используют URL следующего вида:

`https://vulnerable_host/userinfo?username=x`

- Контролируемым пользователем значением является `x` (параметр `username`).

#### Ручная инъекция

Тестировщик может выполнить ручную проверку через веб-браузер или утилиты отладки HTTP API. Перейдите к веб-приложению так, чтобы запрос содержал спецификаторы преобразования. Следует учитывать, что большинство спецификаторов требуют [URL-кодирования](https://tools.ietf.org/html/rfc3986#section-2.1), поскольку содержат специальные символы, включая `%` и `{`. Проверить реакцию на строку `%s%s%s%n` можно с помощью запроса по URL:

`https://vulnerable_host/userinfo?username=%25s%25s%25s%25n`

Если веб-приложение уязвимо, браузер или инструмент тестирования зафиксирует ошибку, выраженную в таймауте соединения или HTTP-ответе с кодом 500.

Код на Java вернет сообщение об ошибке:

`java.util.MissingFormatArgumentException: Format specifier '%s'`

В зависимости от конкретной реализации на C процесс может полностью аварийно завершиться с ошибкой сегментации (`Segmentation Fault`).

#### Фаззинг с использованием инструментов

Инструменты фаззинга, такие как [wfuzz](https://github.com/xmendez/wfuzz), позволяют автоматизировать тестирование на инъекции. Для работы с wfuzz создайте текстовый файл со словарем пейлоадов (в данном примере — `fuzz.txt`), содержащий по одному значению на строку:

fuzz.txt:

```text
alice
%s%s%s%n
%p%p%p%p%p
{event.__init__.__globals__[CONFIG][SECRET_KEY]}
```

Файл `fuzz.txt` содержит следующие тестовые векторы:

- Корректное значение `alice` для проверки штатной обработки нормальных данных
- Две строки со спецификаторами преобразования в стиле C
- Один спецификатор преобразования для Python, нацеленный на чтение глобальных переменных

Для отправки фаззинг-пейлоадов в тестируемое веб-приложение выполните команду:

`wfuzz -c -z file,fuzz.txt,urlencode https://vulnerable_host/userinfo?username=FUZZ`

В этой команде аргумент `urlencode` включает необходимое экранирование строк, а маркер `FUZZ` указывает место подстановки полезной нагрузки.

Пример вывода утилиты:

```text
ID           Response   Lines    Word     Chars       Payload
===================================================================

000000002:   500        0 L      5 W      142 Ch      "%25s%25s%25s%25n"
000000003:   500        0 L      5 W      137 Ch      "%25p%25p%25p%25p%25p"
000000004:   200        0 L      1 W      48 Ch       "%7Bevent.__init__.__globals__%5BCONFIG%5D%5BSECRET_KEY%5D%7D"
000000001:   200        0 L      1 W      5 Ch        "alice"
```

Приведенный результат подтверждает уязвимость приложения к внедрению C-подобных спецификаторов преобразования `%s` и `%p`.
