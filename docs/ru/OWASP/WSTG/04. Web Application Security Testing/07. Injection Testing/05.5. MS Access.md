# MS Access

## Резюме

Как объяснялось в общем разделе [SQL injection](https://owasp.org/www-community/attacks/SQL_Injection), уязвимости внедрения SQL-кода возникают всякий раз, когда пользовательский ввод используется при построении SQL-запроса без достаточных ограничений или санитизации. Этот класс уязвимостей позволяет атакующему выполнять SQL-код с привилегиями учетной записи, используемой для подключения к базе данных. В данном разделе рассматриваются актуальные техники SQL-инъекций, использующие специфические особенности [Microsoft Access](https://en.wikipedia.org/wiki/Microsoft_Access).

## Методика тестирования

### Снятие отпечатков (Fingerprinting)

Идентификация конкретной технологии баз данных при тестировании приложений, использующих SQL, является первым шагом для надлежащей оценки потенциальных уязвимостей. Распространенный подход заключается во внедрении стандартных шаблонов атак SQL Injection (например, одинарной или двойной кавычки и т. д.) с целью вызова исключений базы данных. Если приложение не перехватывает исключения кастомными страницами ошибок, идентифицировать базовую СУБД можно по тексту сообщений об ошибках.

В зависимости от используемой веб-технологии приложения на базе MS Access возвращают одну из следующих ошибок:

`Fatal error: Uncaught exception 'com_exception' with message Source: Microsoft JET Database Engine`

или

`Microsoft JET Database Engine error '80040e14'`

или

`Microsoft Office Access Database Engine`

Во всех этих случаях мы получаем подтверждение того, что тестируемое приложение использует базу данных MS Access.

### Базовое тестирование

К сожалению, MS Access не поддерживает типичные операторы, традиционно применяемые при тестировании на SQL Injection, в том числе:

- Отсутствуют символы комментариев
- Не поддерживаются составные запросы (stacked queries)
- Отсутствует оператор LIMIT
- Отсутствуют операторы задержки вроде SLEEP или BENCHMARK
- и многие другие

Тем не менее эти функции можно эмулировать комбинацией нескольких операторов или использованием альтернативных техник. Как уже отмечалось, стандартный трюк со вставкой символов `/*`, `--` или `#` для усечения запроса здесь не работает. Однако это ограничение можно обойти внедрением нулевого символа (null character). Использование нулевого байта `%00` в SQL-запросе приводит к тому, что MS Access игнорирует все последующие символы. Это объясняется тем, что во внутреннем представлении базы данных все строки являются нуль-терминированными (NULL-terminated). Стоит отметить, что нулевой символ иногда также может вызывать трудности, так как он способен обрезать строки на уровне веб-сервера. В таких ситуациях можно использовать другой символ: `0x16` (`%16` в формате URL-encoding).

Рассмотрим следующий запрос:

`SELECT [username],[password] FROM users WHERE [username]='$myUsername' AND [password]='$myPassword'`

Мы можем усечь запрос с помощью следующих двух URL:

- `https://www.example.com/page.asp?user=admin'%00&pass=foo`
- `https://www.example.com/page.app?user=admin'%16&pass=foo`

Оператор `LIMIT` в MS Access не реализован, однако ограничить количество возвращаемых результатов можно с помощью операторов `TOP` или `LAST`.

`https://www.example.com/page.app?id=2'+UNION+SELECT+TOP+3+name+FROM+appsTable%00`

Комбинируя оба оператора, можно выбирать конкретные результаты. Конкатенация строк осуществляется с помощью символов `& (%26)` и `+ (%2b)`.

Существует также множество других функций, применимых при тестировании SQL-инъекций, включая:

- ASC: возвращает ASCII-код переданного на вход символа
- CHR: возвращает символ по переданному коду ASCII
- LEN: возвращает длину строки, переданной в качестве параметра
- IIF: условная конструкция IF, например выражение `IIF(1=1, 'a', 'b')` возвращает `a`
- MID: функция извлечения подстроки, например выражение `mid('abc',1,1)` возвращает `a`
- TOP: позволяет указать максимальное количество первых записей, возвращаемых запросом. Например, `TOP 1` вернет только 1 строку.
- LAST: используется для выбора только последней строки из набора записей. Например, запрос `SELECT last(*) FROM users` вернет только последнюю строку выборки.

Некоторые из этих операторов критически важны для эксплуатации слепых SQL-инъекций. С другими продвинутыми операторами можно ознакомиться в источниках из раздела ссылок.

#### Перечисление атрибутов

Для перечисления столбцов таблицы базы данных можно использовать распространенную технику на основе ошибок (error-based). Вкратце: имена атрибутов можно получать путем анализа сообщений об ошибках и повторения запроса с различными селекторами. Например, зная имя одного столбца, можно получить имена остальных атрибутов следующим запросом:

`' GROUP BY Id%00`

В полученном сообщении об ошибке можно увидеть имя следующего столбца. Этот метод можно итерировать до тех пор, пока не будут получены имена всех атрибутов. Если имя первого атрибута неизвестно, можно подставить фиктивное имя столбца и получить имя первого реального атрибута в сообщении об ошибке.

#### Получение схемы базы данных

В MS Access по умолчанию существует ряд системных таблиц, которые потенциально можно использовать для получения имен таблиц и столбцов. К сожалению, в конфигурации по умолчанию современных версий MS Access эти таблицы недоступны. Тем не менее всегда стоит попробовать обратиться к:

- MSysObjects
- MSysACEs
- MSysAccessXML

Например, при наличии уязвимости union SQL injection можно использовать следующий запрос:

`' UNION SELECT Name FROM MSysObjects WHERE Type = 1%00`

В качестве альтернативы структуру базы данных всегда можно подобрать перебором по стандартному словарю (например, [FuzzDb](https://github.com/fuzzdb-project/fuzzdb)).

В некоторых случаях разработчики или системные администраторы не осознают, что размещение самого файла `.mdb` в корневом веб-каталоге приложения (webroot) позволяет скачать базу данных целиком. Имена файлов баз данных можно определить с помощью запроса:

`https://www.example.com/page.app?id=1'+UNION+SELECT+1+FROM+name.table%00`

где `name` — имя файла `.mdb`, а `table` — существующая таблица базы данных. Если база данных защищена паролем, для его подбора можно использовать различные утилиты. См. раздел ссылок.

### Тестирование на слепую SQL-инъекцию

Уязвимости слепой SQL-инъекции ([Blind SQL Injection](https://owasp.org/www-community/attacks/Blind_SQL_Injection)) отнюдь не являются самыми простыми в эксплуатации при тестировании реальных приложений. В случае современных версий MS Access выполнение команд оболочки или чтение/запись произвольных файлов также неосуществимы.

В случае слепых SQL-инъекций атакующий может судить о результате выполнения запроса только по разнице во времени ответа или по изменениям в отклике приложения. Предполагается, что читатель уже знаком с теорией атак Blind SQL Injection, поэтому остальная часть этого раздела посвящена специфическим особенностям MS Access.

Рассмотрим следующий пример:

`https://www.example.com/index.php?myId=[sql]`

где параметр ID используется в запросе:

`SELECT * FROM orders WHERE [id]=$myId`

Предположим, что параметр `myId` уязвим к слепой SQL-инъекции. Как атакующий, мы хотим извлечь содержимое столбца `username` в таблице `users`, предполагая, что структура базы данных нам уже известна.

Типичный запрос, используемый для посимвольного вывода первого символа имени пользователя из 10-й строки:

`https://www.example.com/index.php?id=IIF((select%20MID(LAST(username),1,1)%20from%20(select%20TOP%2010%20username%20from%20users)='a',0,'no')`

Если первый символ равен `a`, запрос вернет `0`, в противном случае — строку `no`.

Комбинируя функции `IIF`, `MID`, `LAST` и `TOP`, можно извлечь первый символ имени пользователя в конкретной строке. Поскольку внутренний подзапрос возвращает набор записей, а не одно значение, его нельзя использовать напрямую. К счастью, объединение нескольких функций позволяет извлечь конкретную строку.

Предположим, мы хотим получить имя пользователя из 10-й строки. Сначала мы можем использовать функцию TOP для выбора первых 10 строк с помощью запроса:

`SELECT TOP 10 username FROM users`

Затем из этого подмножества мы можем извлечь последнюю строку с помощью функции LAST. Получив единственную строку, содержащую нужные данные, мы используем функции IIF, MID и LAST для логического вывода значения имени пользователя. В нашем примере мы используем IIF для возврата числа либо строки. С помощью этого приема можно определить истинность результата, наблюдая за ошибками приложения. Поскольку `id` является числовым полем, сравнение со строкой вызывает ошибку SQL, которая может проявиться на странице `500 Internal Server Error`. В противном случае, скорее всего, вернется стандартная страница `200 OK`.

Например, запрос может принять вид:

`https://www.example.com/index.php?id='%20AND%201=0%20OR%20'a'=IIF((select%20MID(LAST(username),1,1)%20from%20(select%20TOP%2010%20username%20from%20users))='a','a','b')%00`

который возвращает TRUE, если первый символ равен 'a', или FALSE в противном случае.

Как отмечалось, данный метод позволяет восстанавливать произвольные строки из базы данных:

1. Путем перебора всех печатных символов до нахождения совпадения
2. Путем предварительного определения длины строки с помощью функции `LEN` либо путем остановки перебора после выявления всех символов

Слепые SQL-инъекции на основе задержек времени также возможны за счет создания тяжелых запросов ([heavy queries](https://learn.microsoft.com/en-us/previous-versions/tn-archive/cc512676(v=technet.10))).
