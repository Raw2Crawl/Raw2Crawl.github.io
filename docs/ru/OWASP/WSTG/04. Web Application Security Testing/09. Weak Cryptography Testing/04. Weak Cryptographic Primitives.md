# Слабые криптографические примитивы

| ID |
| --- |
| WSTG-CRYP-04 |

## Резюме

Некорректное использование алгоритмов шифрования может приводить к раскрытию конфиденциальных данных, утечке ключей, компрометации механизмов аутентификации, небезопасным сессиям и атакам спуфинга (spoofing). Некоторые алгоритмы шифрования или хеширования признаны криптографически слабыми и не рекомендуются к использованию (например, MD5 и RC4).

Помимо правильного выбора стойких алгоритмов шифрования или хеширования, ключевое значение для уровня безопасности имеет корректный выбор их параметров. Например, режим электронной кодовой книги (Electronic Codebook, ECB), как правило, не должен использоваться в принципе.

## Цели тестирования

- Предоставить руководство по выявлению фактов использования и реализации слабых алгоритмов шифрования и хеширования.

## Методика тестирования

### Базовый чек-лист безопасности

- При использовании алгоритмов AES128 или AES256 вектор инициализации (Initialization Vector, IV) должен быть случайным и непредсказуемым. См. стандарт [FIPS 140-3 «Требования безопасности для криптографических модулей»](https://csrc.nist.gov/pubs/fips/140-3/final), раздел тестирования генераторов случайных чисел. Например, в платформе Java класс `java.util.Random` считается слабым генератором случайных чисел. Вместо `java.util.Random` следует использовать криптографически стойкий `java.security.SecureRandom`.
- Для асимметричного шифрования рекомендуется применять криптографию на эллиптических кривых (Elliptic Curve Cryptography, ECC) с безопасными кривыми, предпочтительно `Curve25519`.
    - Если использование ECC невозможно, применяйте шифрование RSA с длиной ключа не менее 2048 бит.
- При использовании алгоритма RSA для формирования цифровой подписи рекомендуется схема дополнения PSS (Probabilistic Signature Scheme).
- Недопустимо использовать слабые алгоритмы хеширования/шифрования, такие как MD5, RC4, DES, Blowfish, SHA1, а также ключи RSA или DSA длиной 1024 бита, кривые ECDSA длиной 160 бит и алгоритм 2TDEA с длиной ключа 80/112 бит (двухключевой Triple DES).
- Требования к минимальной длине ключей:

```text
Key exchange: Diffie-Hellman key exchange with minimum 2048 bits
Message Integrity: HMAC-SHA2
Message Hash: SHA2 256 bits
Asymmetric encryption: RSA 2048 bits
Symmetric-key algorithm: AES 128 bits
Password Hashing: PBKDF2, Scrypt, Bcrypt
ECDH, ECDSA: 256 bits
```

- При использовании SSH запрещено применять режим CBC.
- При использовании симметричных алгоритмов шифрования запрещено применять режим ECB (Electronic Codebook).
- При использовании функции PBKDF2 для хеширования паролей рекомендуется задавать число итераций более 10 000. Институт [NIST](https://pages.nist.gov/800-63-4/sp800-63b.html) также рекомендует не менее 10 000 итераций хеш-функции. Кроме того, запрещено использовать функцию MD5 в сочетании с PBKDF2 (например, PBKDF2WithHmacMD5).

### Анализ исходного кода

- Выполните поиск по следующим ключевым словам для выявления использования устаревших и слабых алгоритмов: `MD4, MD5, RC4, RC2, DES, Blowfish, SHA-1, ECB`.

- В реализациях на Java к шифрованию относятся следующие API. Проверьте параметры, передаваемые в эти реализации:

```java
SecretKeyFactory(SecretKeyFactorySpi keyFacSpi, Provider provider, String algorithm)
SecretKeySpec(byte[] key, int offset, int len, String algorithm)
Cipher c = Cipher.getInstance("DES/CBC/PKCS5Padding");
```

- Для алгоритма шифрования RSA рекомендуются следующие режимы дополнения:

```text
RSA/ECB/OAEPWithSHA-1AndMGF1Padding (2048)
RSA/ECB/OAEPWithSHA-256AndMGF1Padding (2048)
```

- Выполните поиск по ключевому слову `ECB` — этот режим недопустим для использования в схемах дополнения.
- Убедитесь, что для каждой операции шифрования генерируется уникальный вектор инициализации (IV):

```java
// Use a different IV value for every encryption
byte[] newIv = ...;
s = new GCMParameterSpec(s.getTLen(), newIv);
cipher.init(..., s);
...
```

- Выполните поиск по `IvParameterSpec` и проверьте, генерируется ли значение IV уникально и с использованием криптографически стойкого генератора случайных чисел:

```java
 IvParameterSpec iv = new IvParameterSpec(randBytes);
 SecretKeySpec skey = new SecretKeySpec(key.getBytes(), "AES");
 Cipher cipher = Cipher.getInstance("AES/CBC/PKCS5Padding");
 cipher.init(Cipher.ENCRYPT_MODE, skey, iv);
```

- В коде на Java выполните поиск вызовов `MessageDigest`, чтобы убедиться в отсутствии слабых алгоритмов хеширования (MD5 или CRC). Например:

`MessageDigest md5 = MessageDigest.getInstance("MD5");`

- Для формирования цифровой подписи не должны применяться алгоритмы SHA1 и MD5. Например:

`Signature sig = Signature.getInstance("SHA1withRSA");`

- Выполните поиск по ключевому слову `PBKDF2`. Для генерации хеша пароля рекомендуется использовать алгоритм `PBKDF2`. Проанализируйте параметры, передаваемые для вычисления хеш-значения `PBKDF2`.

Число итераций должно превышать **10000**, а значение **соли (salt)** должно генерироваться как **криптографически случайная величина**.

```java
private static byte[] pbkdf2(char[] password, byte[] salt, int iterations, int bytes)
    throws NoSuchAlgorithmException, InvalidKeySpecException
  {
       PBEKeySpec spec = new PBEKeySpec(password, salt, iterations, bytes * 8);
       SecretKeyFactory skf = SecretKeyFactory.getInstance(PBKDF2_ALGORITHM);
       return skf.generateSecret(spec).getEncoded();
   }
```

- Поиск жестко закодированной конфиденциальной информации (hardcoded secrets):

```text
User related keywords: name, root, su, sudo, admin, superuser, login, username, uid
Key related keywords: public key, AK, SK, secret key, private key, passwd, password, pwd, share key, shared key, crypto, base64
Other common sensitive keywords: sysadmin, root, privilege, pass, key, code, master, admin, uname, session, token, Oauth, privatekey, shared secret
```

## Инструменты

- Сканеры уязвимостей, такие как Nessus, Nmap (скрипты NSE) или OpenVAS, могут проверять поддержку слабых алгоритмов шифрования в сетевых протоколах SNMP, TLS, SSH, SMTP и др.
- Инструменты статического анализа исходного кода (SAST), такие как Klocwork, Fortify, Coverity, Checkmarx, для выявления следующих категорий уязвимостей:
