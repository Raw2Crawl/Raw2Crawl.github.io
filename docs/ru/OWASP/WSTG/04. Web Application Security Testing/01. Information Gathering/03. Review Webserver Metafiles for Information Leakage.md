# Анализ метафайлов веб-сервера на утечку информации

| ID |
| --- |
| WSTG-INFO-03 |

## Резюме

В этом разделе описывается, как тестировать различные метафайлы на предмет утечки информации (information leakage) о путях веб-приложения или его функциональности. Кроме того, список каталогов, которых должны избегать поисковые роботы, пауки или краулеры (Spiders, Robots, Crawlers), также может быть сформирован в качестве предварительного условия для выполнения раздела [Map execution paths through application](07.%20Map%20Execution%20Paths%20Through%20Application.md). Также могут быть собраны и другие сведения для определения поверхности атаки (attack surface), деталей используемых технологий или для применения в сценариях социальной инженерии (social engineering).

## Цели тестирования

- Идентифицировать скрытые или обфусцированные пути и функционал посредством анализа метафайлов.
- Извлечь и сопоставить дополнительную информацию, которая может способствовать лучшему пониманию исследуемых систем.

## Методика тестирования

> Любые действия, выполняемые ниже с помощью `wget`, также могут быть выполнены с использованием `curl`. Многие инструменты динамического тестирования безопасности приложений (Dynamic Application Security Testing, DAST), такие как ZAP и Burp Suite, включают проверки или парсинг этих ресурсов в рамках своей функциональности поискового робота/краулера (spider/crawler). Их также можно обнаружить с помощью различных дорков Google ([Google Dorks](https://en.wikipedia.org/wiki/Google_hacking)) или используя расширенные функции поиска, такие как `inurl:`.

### Поисковые роботы (Robots)

Веб-пауки, роботы или краулеры загружают веб-страницу, а затем рекурсивно переходят по гиперссылкам для получения дальнейшего веб-контента. Их общепринятое поведение определяется протоколом исключений для роботов ([Robots Exclusion Protocol](https://datatracker.ietf.org/doc/html/rfc9309)) ([RFC 9309](https://datatracker.ietf.org/doc/html/rfc9309)) с помощью файла `robots.txt` в корневом каталоге веб-сервера (web root directory).

В качестве примера ниже приведен фрагмент файла `robots.txt` с сайта [Google](https://www.google.com/robots.txt), полученный 13 сентября 2026 года:

```text
User-agent: *
User-agent: Yandex
Disallow: /search
Allow: /search/about
Allow: /search/howsearchworks
Disallow: /sdch
Disallow: /groups
...
# Crawlers of certain social media sites are allowed to access page markup when
# google.com/imgres* links are shared. To learn more, please contact
# images-robots-allowlist@google.com.
User-agent: facebookexternalhit
User-agent: Twitterbot
Allow: /imgres
Allow: /search
Disallow: /groups
Disallow: /hosted/images/
Disallow: /m/

Sitemap: https://www.google.com/sitemap.xml
```

Директива [User-Agent](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/User-Agent) указывает на конкретного веб-паука/робота/краулера. Например, `User-Agent: Googlebot` относится к пауку Google, в то время как `User-Agent: bingbot` указывает на краулер компании Microsoft. Директива `User-Agent: *` в приведенном выше примере применяется ко всем [веб-паукам/роботам/краулерам](https://developers.google.com/search/docs/crawling-indexing/robots/intro).

Директива `Disallow` указывает, доступ к каким ресурсам запрещен для пауков/роботов/краулеров. В приведенном выше примере запрещены следующие пути:

```text
...
Disallow: /search
...
Disallow: /sdch
...
```

Веб-пауки/роботы/краулеры могут [намеренно игнорировать](https://blog.cloudflare.com/perplexity-is-using-stealth-undeclared-crawlers-to-evade-website-no-crawl-directives/) директивы `Disallow`, указанные в файле `robots.txt`. Следовательно, `robots.txt` не следует рассматривать как механизм принудительного применения ограничений на доступ к веб-контенту, его хранение или повторную публикацию третьими сторонами.

Файл `robots.txt` запрашивается из корневого веб-каталога веб-сервера. Например, для получения `robots.txt` с `www.google.com` с помощью `wget` или `curl`:

```bash
$ curl -O -Ss https://www.google.com/robots.txt && head -n5 robots.txt
User-agent: *
Disallow: /search
Allow: /search/about
Allow: /search/static
Allow: /search/howsearchworks
...
```

#### ИИ-краулеры

Многие краулеры искусственного интеллекта (ИИ), используемые ИИ-компаниями для сбора обучающих данных, были замечены в игнорировании директив `robots.txt`. Разработчики и владельцы сайтов исследуют контрмеры для защиты своего контента; как описано в [статье TechCrunch 2025 года](https://techcrunch.com/2025/03/27/open-source-devs-are-fighting-ai-crawlers-with-cleverness-and-vengeance/), сообщество разработчиков открытого исходного кода отреагировало такими тактиками, как генерация бесконечного поддельного контента для исчерпания ресурсов краулеров или выдача вводящих в заблуждение данных для снижения качества обучающих выборок ИИ. [Фонд свободного программного обеспечения](https://www.fsf.org/blogs/sysadmin/our-small-team-vs-millions-of-bots) (Free Software Foundation) также задокументировал эксплуатационную нагрузку, которую огромные объемы ИИ-краулеров создают для небольших команд, подчеркивая, что даже благонамеренные правила `robots.txt` регулярно игнорируются.

С точки зрения тестирования, записи в `robots.txt`, предназначенные для блокировки ИИ-краулеров (например, `User-Agent: GPTBot`, `User-Agent: ClaudeBot`), могут оказаться неэффективными, а чувствительные пути, перечисленные в `robots.txt`, остаются доступными для обнаружения любым краулером, игнорирующим протокол.

#### Анализ robots.txt с помощью инструментов Google для веб-мастеров

Владельцы сайтов могут использовать функцию «Analyze robots.txt» для анализа сайта в рамках сервиса [Google Webmaster Tools](https://search.google.com/search-console/about). Этот инструмент может помочь при тестировании, и процедура выглядит следующим образом:

1. Войдите в Google Webmaster Tools под учетной записью Google.
2. На панели управления введите URL-адрес сайта, который необходимо проанализировать.
3. Выберите один из доступных методов и следуйте инструкциям на экране.

### META-теги

Теги `<META>` располагаются внутри секции `HEAD` каждого HTML-документа и должны быть согласованы по всему сайту на случай, если начальная точка робота/паука/краулера начинается со ссылки на документ, отличный от корня сайта, то есть с [глубокой ссылки](https://en.wikipedia.org/wiki/Deep_linking) (deep link). Директива для роботов также может быть задана с помощью специального [метатега](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag).

#### Метатег Robots

Если запись `<META NAME="ROBOTS" ... >` отсутствует, то протокол исключений для роботов по умолчанию принимает значения `INDEX,FOLLOW`. Следовательно, две другие допустимые директивы, определенные протоколом исключений для роботов, имеют префикс `NO...`, то есть `NOINDEX` и `NOFOLLOW`.

На основе директив(ы) `Disallow`, перечисленных в файле `robots.txt` в корневом каталоге, выполняется поиск по регулярному выражению для `<META NAME="ROBOTS"` на каждой веб-странице. Затем полученный результат сравнивается с файлом `robots.txt` в корневом веб-каталоге.

#### Прочие информационные META-теги

Организации часто внедряют информационные метатеги в веб-контент для поддержки различных технологий, таких как программы чтения с экрана (screen readers), предварительный просмотр в социальных сетях, индексация поисковыми системами и т. д. Такая метаинформация может представлять ценность для тестировщиков при определении используемых технологий и выявлении дополнительных путей/функционала для изучения и тестирования. Следующая метаинформация была получена с `www.whitehouse.gov` через пункт меню браузера «Просмотреть исходный код» (View Page Source) 13 сентября 2026 года:

### Карты сайта (Sitemaps)

Файл схемы сайта (sitemap) — это файл, в котором разработчик или организация может предоставить информацию о страницах, видео и других файлах, размещенных на сайте или в приложении, а также о взаимосвязях между ними. Поисковые системы могут использовать этот файл для более эффективной навигации по сайту. Аналогичным образом тестировщики могут использовать файлы `sitemap.xml` для получения более глубокого представления об исследуемом сайте или приложении.

Следующий фрагмент взят из основного sitemap компании Google, полученного 5 мая 2020 года.

```bash
$ wget --no-verbose https://www.google.com/sitemap.xml && head -n8 sitemap.xml
2020-05-05 12:23:30 URL:https://www.google.com/sitemap.xml [2049] -> "sitemap.xml" [1]

<?xml version="1.0" encoding="UTF-8"?>
<sitemapindex xmlns="https://www.google.com/schemas/sitemap/0.84">
  <sitemap>
    <loc>https://www.google.com/gmail/sitemap.xml</loc>
  </sitemap>
  <sitemap>
    <loc>https://www.google.com/forms/sitemaps.xml</loc>
  </sitemap>
...
```

Продолжая исследование отсюда, тестировщик может захотеть получить карту сайта Gmail `https://www.google.com/gmail/sitemap.xml`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="https://www.sitemaps.org/schemas/sitemap/0.9" xmlns:xhtml="https://www.w3.org/1999/xhtml">
  <url>
    <loc>https://www.google.com/intl/am/gmail/about/</loc>
    <xhtml:link href="https://www.google.com/gmail/about/" hreflang="x-default" rel="alternate"/>
    <xhtml:link href="https://www.google.com/intl/el/gmail/about/" hreflang="el" rel="alternate"/>
    <xhtml:link href="https://www.google.com/intl/it/gmail/about/" hreflang="it" rel="alternate"/>
    <xhtml:link href="https://www.google.com/intl/ar/gmail/about/" hreflang="ar" rel="alternate"/>
...
```

### Файл Security TXT

Файл [security.txt](https://securitytxt.org) был ратифицирован IETF как [RFC 9116 — Формат файла для содействия раскрытию уязвимостей безопасности (A File Format to Aid in Security Vulnerability Disclosure)](https://www.rfc-editor.org/rfc/rfc9116.html), который позволяет сайтам определять политики безопасности и контактные данные. Существует несколько причин, по которым он может представлять интерес в сценариях тестирования, включая, помимо прочего:

- Определение дополнительных путей или ресурсов для включения в процессы обнаружения/анализа.
- Сбор информации на основе открытых источников (Open Source Intelligence, OSINT).
- Поиск сведений о программах Bug Bounty и т. д.
- Социальная инженерия (Social Engineering).

Файл может присутствовать либо в корне веб-сервера, либо в каталоге `.well-known/`, например:

- `https://example.com/security.txt`
- `https://example.com/.well-known/security.txt`

Вот реальный пример, полученный из LinkedIn 5 мая 2020 года:

```bash
$ wget --no-verbose https://www.linkedin.com/.well-known/security.txt && cat security.txt
2020-05-07 12:56:51 URL:https://www.linkedin.com/.well-known/security.txt [333/333] -> "security.txt" [1]
# Conforms to IETF `draft-foudil-securitytxt-07`
Contact: mailto:security@linkedin.com
Contact: https://www.linkedin.com/help/linkedin/answer/62924
Encryption: https://www.linkedin.com/help/linkedin/answer/79676
Canonical: https://www.linkedin.com/.well-known/security.txt
Policy: https://www.linkedin.com/help/linkedin/answer/62924
```

Открытые ключи OpenPGP содержат метаданные, которые могут предоставить информацию о самом ключе. Вот некоторые распространенные элементы метаданных, которые могут быть извлечены из открытого ключа OpenPGP:

- **Key ID**: Идентификатор ключа (Key ID) — это короткий идентификатор, полученный из данных открытого ключа. Он помогает идентифицировать ключ и часто отображается в виде восьмизначного шестнадцатеричного значения.
- **Key Fingerprint**: Отпечаток ключа (Key Fingerprint) — это более длинный и уникальный идентификатор, полученный из материала ключа. Обычно он отображается в виде 40-символьного шестнадцатеричного значения. Отпечатки ключей обычно используются для проверки целостности и подлинности открытого ключа.
- **Key Algorithm**: Алгоритм ключа (Key Algorithm) представляет криптографический алгоритм, используемый открытым ключом. OpenPGP поддерживает различные алгоритмы, такие как RSA, DSA и ECC (эллиптическая криптография / Elliptic Curve Cryptography).
- **Key Size**: Размер ключа (Key Size) указывает на длину или размер криптографического ключа в битах. Он определяет стойкость ключа и уровень безопасности, обеспечиваемый ключом.
- **Key Creation Date**: Дата создания ключа (Key Creation Date) указывает, когда ключ был сгенерирован или создан.
- **Key Expiration Date**: Для открытых ключей OpenPGP может быть установлен срок действия, после которого они считаются недействительными. Дата истечения срока действия ключа указывает, когда ключ перестает быть действительным.
- **User IDs**: Открытые ключи могут иметь один или несколько связанных идентификаторов пользователя (User IDs), которые идентифицируют владельца или сущность, связанную с ключом. Идентификаторы пользователей обычно содержат такую информацию, как имя, адрес электронной почты и необязательные комментарии владельца ключа.

### Файл Humans TXT

`humans.txt` — это инициатива, призванная рассказать о людях, стоящих за созданием сайта. Он представляет собой текстовый файл, содержащий информацию о различных специалистах, внесших свой вклад в разработку сайта. Этот файл часто (хотя и не всегда) содержит информацию, связанную со страницами или путями к вакансиям и карьерным порталам компании.

Следующий пример был получен из Google 5 мая 2020 года:

```bash
$ wget --no-verbose  https://www.google.com/humans.txt && cat humans.txt
2020-05-07 12:57:52 URL:https://www.google.com/humans.txt [286/286] -> "humans.txt" [1]
Google is built by a large team of engineers, designers, researchers, robots, and others in many different sites across the globe. It is updated continuously, and built with more tools and technologies than we can shake a stick at. If you'd like to help us out, see careers.google.com.
```

### Другие источники информации в .well-known

Существуют и другие RFC и интернет-проекты (drafts), которые предлагают стандартизированное использование файлов в каталоге `.well-known/`. Списки таких файлов можно найти [на Википедии](https://en.wikipedia.org/wiki/List_of_/.well-known/_services_offered_by_webservers) или [в реестре IANA](https://www.iana.org/assignments/well-known-uris/well-known-uris.xhtml).

Тестировщику будет несложно изучить эти RFC/проекты и составить список для передачи краулеру или фаззеру (fuzzer), чтобы проверить существование или содержимое подобных файлов.
