# Путаница сессий (Session Puzzling)

| ID |
| --- |
| WSTG-SESS-08 |

## Резюме

Перегрузка переменных сессии (Session Variable Overloading, также известная как путаница сессий — Session Puzzling) — это уязвимость уровня приложения, позволяющая атакующему выполнять широкий спектр вредоносных действий, включая (но не ограничиваясь):

- Обход эффективных механизмов принудительной аутентификации и выдача себя за легитимных пользователей.
- Повышение привилегий вредоносной учетной записи пользователя в среде, которая в противном случае считалась бы абсолютно надежной.
- Пропуск обязательных этапов в многошаговых процессах, даже если процесс включает все общепринятые ограничения на уровне кода.
- Манипулирование значениями на стороне сервера косвенными методами, которые невозможно предсказать или обнаружить.
- Проведение традиционных атак в местах, которые ранее были недоступны или даже считались защищенными.

Эта уязвимость возникает, когда приложение использует одну и ту же переменную сессии для нескольких различных целей. Атакующий потенциально может обращаться к страницам в порядке, не предусмотренном разработчиками, так что переменная сессии устанавливается в одном контексте, а затем используется в другом.

Например, атакующий может применить перегрузку переменных сессии для обхода механизмов контроля аутентификации в приложениях, подтверждающих аутентификацию путем проверки наличия переменных сессии с идентификационными данными, которые обычно сохраняются в сессии после успешного входа в систему. Это означает, что злоумышленник сначала обращается к разделу приложения, устанавливающему контекст сессии, а затем запрашивает привилегированные ресурсы, которые проверяют этот контекст.

К примеру, вектор атаки на обход аутентификации может быть реализован путем обращения к общедоступной точке входа (например, странице восстановления пароля), которая заполняет сессию идентичной переменной сессии на основе фиксированных значений или входных данных, поступивших от пользователя.

## Цели тестирования

- Выявить все переменные сессии.
- Нарушить логическую последовательность (flow) формирования сессии.

## Методика тестирования

### Тестирование методом «черного ящика»

Эту уязвимость можно обнаружить и проэксплуатировать путем перечисления всех переменных сессии, используемых приложением, и определения контекстов, в которых они действительны. В частности, это возможно путем обращения к последовательности точек входа с последующим анализом точек выхода. В случае тестирования методом «черного ящика» (black-box) данная процедура сложна и требует определенной доли удачи, поскольку каждая отдельная последовательность может приводить к разному результату.

#### Примеры

Очень простым примером может служить функционал сброса пароля: в точке входа он может запрашивать у пользователя идентификационную информацию, такую как имя пользователя или адрес электронной почты. Затем эта страница может заполнять сессию данными идентификационными значениями, полученными непосредственно от клиента либо сформированными в результате запросов или вычислений на основе принятых данных. В этот момент в приложении могут существовать страницы, отображающие приватные данные на основе этого сессионного объекта. Таким образом атакующий может обойти процесс аутентификации.

### Тестирование методом «серого ящика»

Наиболее эффективным способом выявления данных уязвимостей является аудит исходного кода (source code review).

## Рекомендации по устранению

Переменные сессии должны использоваться только для одной строго определенной цели.
