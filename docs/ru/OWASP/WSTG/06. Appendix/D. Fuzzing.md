# D. Фаззинг {#fuzzing}

## Введение

Фаззинг (fuzzing) — это процесс или методика отправки серии запросов к целевому ресурсу через определенные промежутки времени. Иными словами, он концептуально близок к полному перебору (bruteforcing). Фаззинг реализуется с помощью таких инструментов, как Wfuzz, ffuf и аналогичных утилит. Тестировщик задает утилите целевой URL, параметр, эндпоинт и набор входных значений (wordlist). Затем инструмент генерирует запросы и направляет их к цели. По завершении фаззинга полученные ответы, задержки по времени, коды состояния HTTP и другие характеристики анализируются на предмет потенциальных уязвимостей.

## Зачем нужен фаззинг?

Тестирование на уязвимости путем ручной передачи входных данных по одному крайне трудоемко и неэффективно. В современных реалиях ограниченного времени и высоких требований к скорости ручной перебор параметров для поиска дефектов и уязвимостей создает избыточную нагрузку. Чтобы сократить рутину и сэкономить время, фаззинг становится ключевым инструментом автоматизации. Большую часть черновой работы выполняет специализированная утилита, а аналитику остается лишь проанализировать характеристики ответов по завершении сканирования. Представьте ресурс с десятками полей ввода, которые необходимо проверить на межсайтовый скриптинг (Cross-Site Scripting, XSS). При ручном подходе пришлось бы подставлять XSS-пейлоады в каждое поле по отдельности. При автоматизированном фаззинге достаточно передать список пейлоадов в утилиту, которая сама выполнит всю последовательность запросов.

## Инструменты для фаззинга

В индустрии представлены сотни инструментов для проведения фаззинга. Ниже перечислены некоторые из наиболее популярных и авторитетных решений.

### Wfuzz

[Wfuzz](https://github.com/xmendez/wfuzz) работает по принципу подстановки значений из словаря (wordlist) вместо плейсхолдера `FUZZ`. Для наглядности рассмотрим пример:

```bash
wfuzz -w userIDs.txt https://example.com/view_photo?userId=FUZZ
```

В приведенной команде `userIDs.txt` представляет собой файл словаря, содержащий числовые идентификаторы. Мы указываем Wfuzz выполнить фаззинг запросов по заданному URL. Ключевое слово `FUZZ` в строке URL служит плейсхолдером: Wfuzz последовательно заменяет его на строки из словаря `userIDs.txt`.

### Ffuf

[Ffuf](https://github.com/ffuf/ffuf) — быстрый инструмент веб-фаззинга, написанный на языке Go и поддерживающий рекурсивное сканирование. Принцип его работы аналогичен Wfuzz, однако он отличается высокой производительностью и возможностью рекурсивного обхода. Ffuf также заменяет плейсхолдер `FUZZ` на строки из словаря. Пример:

```bash
ffuf -w userIDs.txt -u https://example.com/view_photo?userId=FUZZ
```

В данной команде флаг `-w` задает файл словаря, а `-u` — целевой URL. В остальном логика работы повторяет Wfuzz: плейсхолдер `FUZZ` замещается значениями из `userIDs.txt`.

### GoBuster

[GoBuster](https://github.com/OJ/gobuster) — еще один популярный инструмент на языке Go, применяемый преимущественно для фаззинга URI, директорий и путей, DNS-поддоменов, бакетов AWS S3, виртуальных хостов (vhost), и поддерживающий многопоточность. Пример:

```bash
gobuster dir -w endpoints.txt -u https://example.com
```

В этой команде аргумент `dir` указывает режим сканирования директорий, `-u` — целевой URL, а `-w` — путь к словарю `endpoints.txt`, откуда извлекаются пейлоады. Утилита отправляет конкурентные запросы к эндпоинту для обнаружения доступных каталогов.

### ZAP

[ZAP](https://www.zaproxy.org) — сканер безопасности веб-приложений для поиска уязвимостей и дефектов реализации. Он включает в себя встроенный модуль фаззинга ([Fuzzer](https://www.zaproxy.org/docs/desktop/addons/fuzzer/)).

Одной из ключевых особенностей ZAP является поддержка как пассивного, так и активного сканирования. Пассивное сканирование анализирует проходящий трафик между клиентом и веб-приложением, тогда как активное сканирование отправляет тестовые пейлоады к приложению для выявления уязвимостей.

### Словари и справочные материалы
