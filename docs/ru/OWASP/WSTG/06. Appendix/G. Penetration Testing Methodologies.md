# Методологии тестирования на проникновение

В данном приложении систематизированы признанные методологии и отраслевые фреймворки тестирования на проникновение. Эти стандарты содержат подробные руководства по процедурам, фазам и формированию отчетности по результатам проверок. [Методология тестирования OWASP (OWASP Testing Framework)](../03.%20The%20OWASP%20Testing%20Framework/index.md) (Раздел 3) описывает то, *когда* необходимо проводить тестирование и какие техники следует применять. Настоящее приложение систематизирует практический аспект (*как именно* проводить работы) — структурированные методологии, на которые специалисты могут опираться при проведении официальных проектов по тестированию на проникновение.

## Руководства по тестированию OWASP

Проект OWASP развивает и поддерживает руководства по тестированию для различных типов систем:

- [OWASP Web Security Testing Guide](https://wstg.owasp.org/) — веб-приложения и веб-сервисы
- [OWASP Mobile Security Testing Guide](https://mas.owasp.org/) — мобильные приложения для iOS и Android
- [OWASP Firmware Security Testing Methodology](https://github.com/scriptingxss/owasp-fstm) — встроенные системы и микропрограммное обеспечение (firmware)
- [OWASP AI Testing Guide](https://owasp.org/projects/ai-testing-guide) — приложения на базе искусственного интеллекта и больших языковых моделей (LLM)

## Руководство PCI по тестированию на проникновение

[Требование 11.3 стандарта PCI DSS](https://www.pcisecuritystandards.org/documents/Penetration-Testing-Guidance-v1_1.pdf) предписывает обязательное проведение тестирования на проникновение для организаций, обрабатывающих данные платежных карт. Руководство PCI регламентирует:

- Компоненты тестирования на проникновение и квалификационные требования к специалистам
- Общепринятые отраслевые методологии тестирования
- Охват среды данных владельцев карт (Cardholder Data Environment, CDE) и критических систем
- Требования к внешнему и внутреннему тестированию
- Тестирование прикладного уровня (application-layer) и сетевого уровня (network-layer)
- Процедуры верификации области оценки (scope) и регламент тестирования

## Фреймворк тестирования на проникновение

Фреймворк тестирования на проникновение (Penetration Testing Framework, PTF) являлся комплексным практическим руководством по пентесту, однако проект более активно не поддерживается. Для исторической справки: он структурировал мероприятия по направлениям сетевой разведки (footprinting), обнаружения узлов, перечисления сервисов, оценки уязвимостей и специализированных областей тестирования (беспроводные сети, VoIP, физическая безопасность). В современной практике специалистам рекомендуется обращаться к актуальным стандартам (NIST SP 800-115, OSSTMM) и руководствам OWASP.

## Техническое руководство по тестированию и оценке информационной безопасности

Специальная публикация [NIST SP 800-115](https://csrc.nist.gov/publications/detail/sp/800-115/final) представляет собой технический справочник по тестированию и оценке информационной безопасности, охватывающий:

- Техники аудита (экспертиза документации, анализ кода, тестирование безопасности)
- Техники идентификации и анализа целей (активная и пассивная разведка)
- Техники валидации уязвимостей целевых систем (динамический и статический анализ)
- Планирование и проведение оценки безопасности
- Мероприятия после завершения тестирования (анализ результатов и формирование отчетности)

Смежный документ [NIST SP 800-218 (Secure Software Development Framework, SSDF)](https://csrc.nist.gov/publications/detail/sp/800-218/final) содержит расширенные рекомендации по практикам безопасной разработки на всех этапах жизненного цикла ПО (SDLC).

## Open Source Security Testing Methodology Manual (OSSTMM)

[OSSTMM](https://www.isecom.org/OSSTMM.3.pdf) — всеобъемлющая методология тестирования операционной безопасности физических объектов, бизнес-процессов и технических систем. Она охватывает:

- Анализ безопасности и оценку рисков
- Тестирование человеческого фактора (социальная инженерия, осведомленность)
- Тестирование физической безопасности
- Тестирование безопасности беспроводных сетей и телекоммуникаций
- Тестирование безопасности сетей передачи данных
- Процедуры проверки соответствия и аудита
- Формирование отчетности на основе фреймворка STAR (Security Test Audit Report)

Методология OSSTMM часто применяется в качестве стандарта при аудитах соответствия и оценке операционных рисков, гармонично дополняя техническое тестирование уязвимостей.

## Эмуляция действий злоумышленника и MITRE ATT&CK

В дополнение к классическим методологиям тестирования на проникновение, учения по эмуляции действий противника (adversary emulation) выстраивают процесс тестирования вокруг реальных техник и тактик злоумышленников. База знаний [MITRE ATT&CK](https://attack.mitre.org/) представляет собой общедоступную матрицу тактик и техник атакующих, составленную на основе анализа реальных киберинцидентов. Команды безопасности и Red Team применяют ATT&CK для:

- Выстраивания сценариев тестирования на проникновение по реалистичным цепочкам атак (attack paths)
- Приоритизации моделирования угроз и инвестиций в средства защиты
- Проектирования правил детектирования (detection engineering) и процессов проактивного поиска угроз (threat hunting)

Матрица ATT&CK дополняет классические методологии пентеста единой таксономией и взглядом со стороны атакующего (adversary-focused perspective), в отличие от фокуса исключительно на фазах тестирования или конкретных инструментах.
