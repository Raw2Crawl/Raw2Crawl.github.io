## Руководства OWASP по тестированию

Для проведения технического тестирования безопасности настоятельно рекомендуется использовать руководства OWASP. Ниже перечислены руководства для веб-сервисов и облачных сервисов, мобильных приложений (Android/iOS) и встроенного ПО устройств Интернета вещей соответственно; выбор зависит от типа приложения.

- [Руководство OWASP по тестированию безопасности веб-приложений](https://owasp.org/www-project-web-security-testing-guide/)
- [Руководство OWASP по тестированию безопасности мобильных приложений](https://owasp.org/www-project-mobile-security-testing-guide/)
- [Методология OWASP по тестированию безопасности встроенного ПО](https://github.com/scriptingxss/owasp-fstm)

## Стандарт проведения тестирования на проникновение

Стандарт проведения тестирования на проникновение (Penetration Testing Execution Standard, PTES) выделяет 7 этапов тестирования на проникновение. В частности, технические рекомендации PTES содержат практические советы по процедурам тестирования и рекомендации по инструментам проверки безопасности.

- Предварительное согласование взаимодействия
- Сбор разведывательной информации
- Моделирование угроз
- Анализ уязвимостей
- Эксплуатация
- Действия после эксплуатации
- Отчётность

[Технические рекомендации PTES](http://www.pentest-standard.org/index.php/PTES_Technical_Guidelines)

## Руководство PCI по тестированию на проникновение

Требование 11.3 стандарта безопасности данных индустрии платёжных карт (Payment Card Industry Data Security Standard, PCI DSS) определяет тестирование на проникновение. PCI также выпускает рекомендации по тестированию на проникновение.

### Рекомендации PCI DSS по тестированию на проникновение

Руководство PCI DSS по тестированию на проникновение содержит рекомендации по следующим вопросам:

- составляющие тестирования на проникновение;
- квалификация специалиста по тестированию на проникновение;
- методики тестирования на проникновение;
- рекомендации по отчётности о тестировании на проникновение.

### Требования PCI DSS к тестированию на проникновение

Требования PCI DSS отсылают к требованию 11.3 стандарта безопасности данных индустрии платёжных карт (PCI DSS).

- Основа — общепринятые в отрасли подходы
- Охват среды данных держателей карт (CDE) и критически важных систем
- Включение внешнего и внутреннего тестирования
- Проверка обоснованности сокращения области охвата
- Тестирование на уровне приложений
- Тесты сетевого уровня для сети и ОС

[Рекомендации PCI DSS по тестированию на проникновение](https://www.pcisecuritystandards.org/documents/Penetration_Testing_Guidance_March_2015.pdf)

## Методология тестирования на проникновение

Методология тестирования на проникновение (Penetration Testing Framework, PTF) представляет собой подробное практическое руководство. В ней также перечислены способы применения инструментов тестирования безопасности для каждой категории проверок. Основные области тестирования на проникновение включают:

- сбор сведений о сети (разведку);
- обнаружение и зондирование;
- перечисление объектов;
- взлом паролей;
- оценку уязвимостей;
- аудит AS/400;
- специализированное тестирование Bluetooth;
- специализированное тестирование Cisco;
- специализированное тестирование Citrix;
- магистральную сеть;
- специализированные проверки серверов;
- безопасность VoIP;
- тестирование беспроводных сетей на проникновение;
- физическую безопасность;
- итоговый отчёт — шаблон.

[Методология тестирования на проникновение](http://www.vulnerabilityassessment.co.uk/Penetration%20Test.html)

## Техническое руководство по тестированию и оценке информационной безопасности

Техническое руководство по тестированию и оценке информационной безопасности (NIST 800-115), опубликованное NIST, включает некоторые из перечисленных ниже методов оценки.

- Методы анализа
- Методы идентификации и анализа целей
- Методы подтверждения уязвимостей целей
- Планирование оценки безопасности
- Проведение оценки безопасности
- Мероприятия после тестирования

Документ NIST 800-115 доступен [здесь](https://csrc.nist.gov/publications/detail/sp/800-115/final).

## Открытое руководство по методологии тестирования безопасности

Открытое руководство по методологии тестирования безопасности (Open Source Security Testing Methodology Manual, OSSTMM) — это методология проверки эксплуатационной безопасности физических объектов, рабочих процессов, безопасности человеческого фактора, физической безопасности, безопасности беспроводных сетей, телекоммуникаций и сетей передачи данных, а также соответствия требованиям. OSSTMM может служить вспомогательным источником для ISO 27001, а не практическим или техническим руководством по тестированию приложений на проникновение.

OSSTMM включает следующие ключевые разделы:

- анализ безопасности;
- метрики эксплуатационной безопасности;
- анализ доверия;
- рабочий процесс;
- тестирование безопасности человеческого фактора;
- тестирование физической безопасности;
- тестирование безопасности беспроводных сетей;
- тестирование безопасности телекоммуникаций;
- тестирование безопасности сетей передачи данных;
- нормативные требования к соответствию;
- отчётность с использованием STAR (Security Test Audit Report — отчёта об аудите тестирования безопасности).

[Открытое руководство по методологии тестирования безопасности](https://www.isecom.org/OSSTMM.3.pdf)
