# Анализ содержимого веб-страниц на предмет утечки информации

|ID          |
|------------|
|WSTG-INFO-05|

## Краткое описание

Программисты очень часто включают в исходный код подробные комментарии и метаданные; это даже рекомендуется. Однако комментарии и метаданные в HTML-коде могут раскрыть внутреннюю информацию, которая не должна быть доступна потенциальным злоумышленникам. Необходимо анализировать комментарии и метаданные, чтобы установить, не происходит ли утечка информации.

В современных веб-приложениях всё популярнее использование JavaScript на стороне клиента для реализации пользовательского интерфейса. Его используют популярные технологии построения интерфейса, такие как ReactJS, AngularJS и Vue. Как и в случае комментариев и метаданных HTML, многие программисты жёстко задают конфиденциальные сведения в переменных JavaScript на стороне клиента. Это могут быть, помимо прочего, закрытые ключи API, *например* ключ Google Map API без ограничений, внутренние IP-адреса, конфиденциальные маршруты, *например* пути к скрытым административным страницам или функциям, и даже учётные данные. Эти сведения могут утечь из клиентского JavaScript-кода. Необходимо проверить, не раскрываются ли конфиденциальные сведения, которыми злоумышленники могут воспользоваться во вред.

Для крупных веб-приложений производительность — серьёзная забота программистов. Для оптимизации клиентской части применяются различные методы, в том числе Syntactically Awesome Style Sheets (SASS), Sassy CSS (SCSS), webpack и т. д. При использовании этих технологий клиентский код иногда становится сложнее понимать и отлаживать, поэтому программисты часто размещают файлы карт исходного кода для отладки. Карта исходного кода (source map) — специальный файл, связывающий минифицированную или обфусцированную версию ресурса CSS или JavaScript с исходной авторской версией. Программисты всё ещё спорят о том, следует ли размещать такие карты в производственной среде. Однако нельзя отрицать, что опубликованные там карты исходного кода или файлы отладки делают исходный код удобнее для чтения человеком. Это может облегчить злоумышленникам поиск уязвимостей в клиентской части или сбор конфиденциальных сведений. Необходимо проанализировать JavaScript-код, чтобы выяснить, не доступны ли отладочные файлы клиентской части. В зависимости от контекста и чувствительности проекта специалист по безопасности должен решить, допустимо ли наличие этих файлов в производственной среде.

## Цели тестирования

- Проанализировать комментарии и метаданные веб-страниц для обнаружения утечек информации.
- Собрать файлы JavaScript и проанализировать JS-код, чтобы лучше понять приложение и выявить утечки информации.
- Установить, существуют ли карты исходного кода или другие отладочные файлы клиентской части.

## Методика тестирования

### Анализ комментариев и метаданных веб-страниц

Разработчики часто используют HTML-комментарии для размещения отладочной информации о приложении. Иногда о них забывают и оставляют в производственной среде. Тестировщикам следует искать HTML-комментарии, начинающиеся с `<!--`.

Проверьте исходный HTML-код на наличие комментариев с конфиденциальными сведениями, которые могут помочь злоумышленнику больше узнать о приложении. Это может быть SQL-код, имена пользователей и пароли, внутренние IP-адреса или отладочная информация.

```html
...
<div class="table2">
  <div class="col1">1</div><div class="col2">Mary</div>
  <div class="col1">2</div><div class="col2">Peter</div>
  <div class="col1">3</div><div class="col2">Joe</div>

<!-- Query: SELECT id, name FROM app.users WHERE active='1' -->

</div>
...
```

Тестировщик может найти даже нечто подобное:

```html
<!-- Use the DB administrator password for testing:  f@keP@a$$w0rD -->
```

Проверьте сведения о версии HTML: корректность номеров версий и URL определения типа данных (DTD).

```html
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd">
```

- `strict.dtd` — строгое DTD по умолчанию
- `loose.dtd` — нестрогое DTD
- `frameset.dtd` — DTD для документов с наборами фреймов

Некоторые теги `META` не предоставляют непосредственных векторов атаки, но позволяют злоумышленнику составить представление о приложении:

```html
<META name="Author" content="Andrew Muller">
```

Распространённый тег `META`, не соответствующий [WCAG](https://www.w3.org/WAI/standards-guidelines/wcag/), — [Refresh](https://en.wikipedia.org/wiki/Meta_refresh).

```html
<META http-equiv="Refresh" content="15;URL=https://www.owasp.org/index.html">
```

Тег `META` часто используют для задания ключевых слов, которые поисковая система может учитывать для повышения качества результатов поиска.

```html
<META name="keywords" lang="en-us" content="OWASP, security, sunshine, lollipops">
```

Хотя большинство веб-серверов управляет индексированием поисковыми системами через файл `robots.txt`, для этого можно использовать и теги `META`. Следующий тег рекомендует роботам не индексировать содержащую его HTML-страницу и не переходить по её ссылкам.

```html
<META name="robots" content="none">
```

[Платформа отбора интернет-контента (PICS)](https://www.w3.org/PICS/) и [протокол описания веб-ресурсов (POWDER)](https://www.w3.org/2007/powder/) предоставляют инфраструктуру для связывания метаданных с интернет-контентом.

### Выявление JavaScript-кода и сбор файлов JavaScript

Программисты часто жёстко задают конфиденциальные сведения в переменных JavaScript на стороне клиента. Тестировщикам следует проверить исходный HTML-код и найти JavaScript-код между тегами `<script>` и `</script>`. Следует также выявить внешние файлы JavaScript для анализа кода: они имеют расширение `.js`, а имя файла обычно указывается в атрибуте `src` (источник) тега `<script>`.

Проверьте JavaScript-код на утечки конфиденциальных сведений, которые злоумышленники могут использовать для дальнейшего злоупотребления системой или манипулирования ею. Ищите ключи API, внутренние IP-адреса, конфиденциальные маршруты и учётные данные. Например:

```javascript
const myS3Credentials = {
  accessKeyId: config('AWSS3AccessKeyID'),
  secretAcccessKey: config('AWSS3SecretAccessKey'),
};
```

Тестировщик может найти даже нечто подобное:

```javascript
var conString = "tcp://postgres:1234@localhost/postgres";
```

Обнаружив ключ API, тестировщики могут проверить, заданы ли для него ограничения по сервису, IP-адресу, HTTP referrer, приложению, SDK и т. д.

Например, обнаружив ключ Google Map API, можно проверить, ограничен ли он по IP-адресу или только определёнными Google Map API. Если ключ Google API ограничен только определёнными Google Map API, злоумышленники всё ещё могут использовать его для запросов к Google Map API, доступ к которым не ограничен, а оплачивать их придётся владельцу приложения.

```html

<script type="application/json">
...
{"GOOGLE_MAP_API_KEY":"AIzaSyDUEBnKgwiqMNpDplT6ozE4Z0XxuAbqDi4", "RECAPTCHA_KEY":"6LcPscEUiAAAAHOwwM3fGvIx9rsPYUq62uRhGjJ0"}
...
</script>
```

В некоторых случаях в JavaScript-коде можно найти конфиденциальные маршруты, например ссылки на внутренние или скрытые административные страницы.

```html
<script type="application/json">
...
"runtimeConfig":{"BASE_URL_VOUCHER_API":"https://staging-voucher.victim.net/api", "BASE_BACKOFFICE_API":"https://10.10.10.2/api", "ADMIN_PAGE":"/hidden_administrator"}
...
</script>
```

### Выявление карт исходного кода

Карты исходного кода обычно загружаются при открытии инструментов разработчика. Их также можно искать, добавляя расширение «.map» после расширения каждого внешнего файла JavaScript. Например, обнаружив `/static/js/main.chunk.js`, тестировщик может проверить его карту исходного кода по адресу `/static/js/main.chunk.js.map`.

#### Тестирование методом «чёрного ящика»

Проверьте карты исходного кода на наличие конфиденциальных сведений, которые могут помочь злоумышленнику больше узнать о приложении. Например:

```json
{
  "version": 3,
  "file": "static/js/main.chunk.js",
  "sources": [
    "/home/sysadmin/cashsystem/src/actions/index.js",
    "/home/sysadmin/cashsystem/src/actions/reportAction.js",
    "/home/sysadmin/cashsystem/src/actions/cashoutAction.js",
    "/home/sysadmin/cashsystem/src/actions/userAction.js",
    "..."
  ],
  "..."
}
```

При загрузке карт исходного кода сайтом исходный код клиентской части становится удобным для чтения и более простым для отладки.
